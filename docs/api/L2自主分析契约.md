# L2 自主分析契约

本文描述 factory-agent 的缓存优先自主分析入口，以及宿主与 `sageql-core` 之间的进程内协议。
L2 使用既有 interaction、SSE、结果卡片、历史消息、导出与审计流程。业务客户端继续提交自然语言
问题，不直接调用分析工具，不上传分析计划，不选择数据源、身份或范围。

本契约以 `SECURITY.md`、现行产品需求与客户接口契约为授权和口径依据。语义目录版本为
`factory-analytics-v2.1`；SageQL 公共协议版本为 `1`，当前锁定发行包为 `sageql-core 0.1.0`。
数据源出现在目录中表示具有受控适配路径；某次请求能否回答，仍取决于权限、实体关系、字段验证、
完整性、覆盖及预算。本文不代替客户环境验收记录。

## 1. 业务入口与结果

L1 能完整表达用户条件时，执行受审确定性配方。无法完整表达且具有获准来源时，使用
`l2_analysis` 入口。例如识别到“产量”不能丢弃用户指定的床号，再按普通产量配方回答。
缺少必要条件进入澄清；权限拒绝、数据故障、预算耗尽、取消与超时均保持各自终态。

对外 HTTP 路径、认证、SSE 重放与终态语义沿用
[AI 助手前端对接 API 文档](AI助手前端对接API文档.md)。主要结果字段如下。

| 字段 | L2 含义 |
| --- | --- |
| `capability_id` | `l2_analysis` |
| `columns`、`column_titles` | 经确定性计算与验证的结果列及标题 |
| `row_count` | 当前结果行数；不能作为未读取全集的总记录数 |
| `card` | 既有表格卡片，使用批准结果构建；附属结果按现有明细表结构交付 |
| `incomplete`、`incomplete_reason` | 是否完整及批准的降级分类；不把预算截断包装成完整总数 |
| `time_range` | 有事实窗口时使用带时区的半开区间；纯知识和无时间维度的配置问题可为空或缺席 |
| `answer` | 从批准知识或结果值确定性组织的解释，附可见范围、条件与业务口径 |
| `artifact_id` | 按既有导出流程生成的产物引用，仍受原访问和保留规则约束 |

内部数据句柄和结果引用不作为客户端可复用的请求参数，不可跨 interaction、租户或身份使用。
模型直接生成的数字、文字和文档示例值不能成为工厂数据结果。

## 2. 时间与条件

事实查询继承宿主已解析的时间范围。`window_start` 与 `window_end` 同时为空时表示使用该范围；
显式提供时必须成对、带时区、起点早于终点，且位于原请求范围内。首期事实读取只支持工厂时区的
完整日边界。包含今天与历史窗口继续使用现有缓存策略，不把分别取得的历史与实时数据拼为未经验证
的统一快照。

| 查询 | 日期含义 |
| --- | --- |
| `reported_production`、`time_basis=reported` | 窗口内发生的报工贡献 |
| `reported_production`、`time_basis=audited` | 窗口内审核的获准贡献；必须有已验证审核日期字段 |
| `production_progress` | 按真实制单业务日期选取制单；实收量为这些制单截至查询时刻的累计实收量 |
| 字典与配置 | 默认没有事实时间窗口；生成时间表示取得该配置快照的时刻 |
| 纯知识解释 | 无事实窗口，无 MES 业务取数要求 |

例如工厂时区为 `Asia/Shanghai`，在 2026-10-13 查询“床号 1555 上个月报工量”，窗口为
`[2026-09-01T00:00:00+08:00, 2026-10-01T00:00:00+08:00)`。
选择报工事实，不能用制单日期筛选进度来代替；较早制单在上月发生的报工仍属于该窗口。

床号、款号、计划号和制单号使用字符串等值语义。`1555` 不匹配 `11555` 或 `15550`，也不默认
等同于 `01555`。接口候选下推不改变宿主最终精确过滤。模型增加的查询条件只能在已获准范围内
收窄；实际使用的时间、筛选和配置状态必须随结果说明，不能将子集标注为原问题全集。

床号定位依赖可见事实窗口。窗口内无匹配不证明床号不存在；没有全生命周期覆盖证明时，不把缓存
窗口或近一年当作全历史。

## 3. 逻辑数据集

下列名称是宿主公开给规划器的规范化名称。客户地址、认证材料、原始响应集合和字段映射留在
`data_api`，不出现在模型工具契约中。

| `dataset_id` | 主要字段 | 用途与计数 |
| --- | --- | --- |
| `reported_production` | `plan_code`、`bed_code`、`style_id`、`style_code`、`process_id`、`process_name`、`color`、`size`、`department`、`business_date`、`quantity`、`payroll_amount`、`source_type` | 报工或审核贡献，已确认数量/工资合计、实际出现工序/尺码/计划号的去重数 |
| `production_progress` | 上述维度及 `bill_code`、`package_code`、`issued_quantity`、`received_quantity` | 真实制单日期窗口下的进度贡献，发卡/累计实收量及可见制单等维度 |
| `styles` | `style_id`、`style_code`、`name`、`type_id`、`unit` | 真实款号目录和内部编码解析 |
| `style_types` | `type_id`、`parent_type_id`、`name`、`deleted` | 货号档案分组；年份档案桶不能解释为服装品类 |
| `production_types` | `type_id`、`name`、`deleted`、`counts_cutting`、`counts_stock` | 当前租户实际生产类型字典 |
| `processes` | `process_id`、`name`、`type_name`、`vehicle_type`、`flow_type`、`deleted`、`sort_order` | 工序字典；工序名称、生产类型名称和车种分别保留 |
| `style_processes` | `configuration_id`、`style_id`、`style_code`、`process_id`、`name`、`type_id`、`type_name`、`sort_order`、`active`、`last_process` | 款号配置工序种类与配置记录数 |
| `style_colors` | `configuration_id`、`style_id`、`color` | 获准款号实体的完整颜色配置 |
| `style_sizes` | `configuration_id`、`style_id`、`size`、`fit`、`weight` | 获准款号实体的完整尺码/版型配置 |
| `bill_processes` | `configuration_id`、`bill_code`、`style_id`、`style_code`、`process_id`、`name`、`type_id`、`type_name`、`sort_order`、`last_process` | 从获准进度视图解析的真实制单配置工序 |
| `hanging_lines` | `configuration_id`、`system_name`、`line_code`、`group_name` | 当前租户吊挂线别组别；没有已确认部门关系时不能用于扩大事实范围 |

字段定义存在不代表本次响应已包含并验证该字段。`FieldDescriptor.validated` 表示当前获准数据是否
具备可计算字段；缺列、非法日期、无效 Decimal、未知关系均使相关分析不可用，不能补零。

员工和部门目录继续用于宿主可信身份解析和范围核对，不作为向规划器开放个人身份的明细数据集。
两族事实均使用现行 V2；退役制单映射、被 V2 替代的工资/产量/进度 V1 事实链不进入可执行目录。
包含秘密配置的系统配置源、弃用计划、写操作和未确认吊挂事实也不可由 L2 重新启用。

## 4. 字典授权与实体来源

员工、组长、管理、老板均可读取**当前租户**批准的基础字典和配置安全投影。租户隔离、活动身份
校验和暂停租户门禁仍先于工具和取数。该字典读取权限不改变任何生产事实或工资能力的角色矩阵。

事实动作逐次映射现有权限。员工及明确的本人问题保持本人范围；组长、管理保持绑定部门和 MES
过滤状态；老板保持本厂范围。工资计算额外校验已有工资能力。模型和用户提供的身份编号不能替换
`TenantContext` 或 `DataScope`，目录名册不能成为扩大业务范围的理由。

款号颜色/尺码配置需要先从真实款号目录按业务款号解析内部实体。模型无需看到内部实体实例，
宿主可从本 interaction 已登记的授权数据句柄中解析它们。制单配置只能从获准的进度句柄取得真实
制单集合，再有界读取各制单配置。直接拼一个制单编号不构成授权来源。

按实体缓存的数据只证明对应实体子集完整，不表示全租户目录完整。款号配置与实际制单配置可能
不同，不能相互替代；已报工工序和含未扫码贡献的进度明细也不能自动证明全部配置工序。

## 5. 七个工具

所有工具参数使用严格模型，未知字段被拒绝。每次动作先检查活动身份、宿主授权、句柄来源和共享
预算；模型无法指定 Redis 键、客户 URL、凭据、自由 SQL、Python 或 shell。

| 工具 | 参数结构 | 返回证据 |
| --- | --- | --- |
| `discover_datasets` | `{"goal": "..."}` | 当前获准的规范化数据描述 |
| `lookup_knowledge` | `{"query": "..."}` | 已审核、当前版本知识片段及来源引用 |
| `describe_dataset` | `{"dataset_id": "..."}` | 字段、粒度、指标、日期和范围状态 |
| `ensure_dataset` | `{"query": Query}` | 已授权数据句柄、完整性及交互/缓存/回源状态 |
| `inspect_dataset` | `{"dataset_ref": "..."}` | 行数、空集、字段和覆盖状态，不含原始行 |
| `analyze_dataset` | `{"plan": AnalysisPlan}` | 验证后 `ResultTable` 的不透明结果引用 |
| `finish_or_clarify` | `{"submission": Submission}` | 宿主认可的结果/知识提交，澄清或不可用结论 |

### 5.1 Query

| 字段 | 类型与约束 |
| --- | --- |
| `dataset_id` | 当前获准逻辑数据集名称 |
| `columns` | 所需规范化列，最多 64 列；空列表不取消计算必需字段验证 |
| `filters` | 最多 16 个 `{field, operator, values}`；宿主载入首期接受 `eq` 与 `in`，值列表最多 100 项 |
| `window_start`、`window_end` | 可空、成对的带时区时间；事实使用宿主范围，配置与知识无需填写 |
| `semantics` | `{name, value}` 列表；事实口径为 `time_basis`、`source_type`，名称不重复 |
| `limit` | 结果装载上限，默认 250000，schema 最大 1000000；不提高宿主累计行数预算 |

报工事实的 `time_basis` 为 `reported` 或 `audited`；`source_type` 为 `all`、`scan`、`hanging`、
`manual`。不同口径不混用缓存或句柄。进度当前只接受默认口径；配置不接受事实语义参数。
缺少已确认日期锚的待审核口径不可执行。

以下为合成的工具参数示例，时间及床号不代表任何工厂数据。

```json
{
  "tool": "ensure_dataset",
  "arguments": {
    "query": {
      "dataset_id": "reported_production",
      "columns": ["bed_code", "plan_code", "business_date", "quantity"],
      "filters": [{"field": "bed_code", "operator": "eq", "values": ["1555"]}],
      "window_start": "2026-09-01T00:00:00+08:00",
      "window_end": "2026-10-01T00:00:00+08:00",
      "semantics": [{"name": "time_basis", "value": "reported"}],
      "limit": 250000
    }
  }
}
```

### 5.2 AnalysisPlan

| 字段 | 类型与约束 |
| --- | --- |
| `dataset_refs` | 本 interaction 已登记的句柄，1–4 个；不得重复或跨身份复用 |
| `group_by` | 最多 8 个已验证获准维度；有歧义时使用 `dataset_id.field` |
| `metrics` | 最多 16 个 `{metric_id, operation}`；操作为 `sum`、`count`、`count_distinct`，业务语义须在宿主目录中登记 |
| `filters` | 已验证列上的结构化等值、集合、下界或排他上界条件，绑定参数执行 |
| `order_by` | 最多 8 个 `{field, direction}`；仅排序本计划输出列，方向为 `asc` 或 `desc` |
| `time_bucket` | 可空；`{field: "business_date", unit: "day" \| "week" \| "month"}` |
| `joins` | 最多 3 个有界关联；显式左右引用、键及 `one_to_one` 或 `many_to_one` 基数 |
| `limit` | 1–10000，默认 1000；取到额外一行证明截断时返回 incomplete，不提交伪造完整结果 |

宿主生成受控只读 SQL，在 interaction 唯一 DuckDB 中执行。首期仅接受登记的事实到款号/工序
字典、配置到款号/工序/类型字典关联。右键必须唯一，非空键和实际覆盖必须验证；不能使用名称
猜关系。当前拒绝两族事实 JOIN、多对多关联、自关联和未登记键。

### 5.3 Submission

| `kind` | 必需内容 |
| --- | --- |
| `result` | 本轮经过宿主验证的非空 `result_refs`，不携带自由答案文字 |
| `knowledge` | 本轮批准的非空 `knowledge_refs`，不冒充工厂实例或数据计数 |
| `clarify` | 非空 `clarification`，不携带结果/知识引用 |
| `unavailable` | 批准的不可用分类，不携带未经验证的数据引用 |

所有引用先由 core 核对是否出现在本轮安全观察，再由宿主校验所有权、当前有效性和提交证据。
未知引用、旧 interaction 引用和伪造引用不会成为结果。

## 6. 指标、配置与单位

| 输出 | 口径与单位 |
| --- | --- |
| `quantity` 合计 | 已确认报工贡献，**件·工序**；同一衣物多工序贡献不能解释为独立成衣完工件数 |
| `payroll_amount` 合计 | 已批准工资贡献，**元**；只在可信宿主中计算，个人明细不进入模型 |
| `issued_quantity`、`received_quantity` 合计 | 发卡数量、实收数量，**件**；进度日期筛选制单，实收为截至查询时刻累计值 |
| `process_id`、`size` 等去重计数 | 非空原始标识的种类数，**种**；不自动合并名称或同义编码 |
| `configuration_id` 记录计数 | 配置记录数，**条**；与工序/尺码种类数分别展示 |

配置默认保留使用状态；筛选使用中配置时回显明确条件。重复绑定同一工序时，配置记录数与工序
种类数可能不同。尺码保留编码和版型，不将 XXL 与 2XL 自行合并。实际生产过的工序或尺码来自
事实窗口，不能称作全部配置。

目前不接受模型定义新业务公式、自由比率、工资排名绕过、独立成衣完工件数推断或没有稳定编码
证明的关系。已确认完工率知识可以解释；能解释一个公式不代表该公式已成为本期 L2 的可执行指标。

## 7. 缓存与完整性

`ensure_dataset` 顺序为：本 interaction 已授权且覆盖足够的句柄 → 既有 API 数据缓存 →
受同一授权与预算约束的必要回源。相同规范化请求在交互内合并；已证明的完整空集继续复用。
款号表单保留款号、颜色、尺码各集合的验证和计数证据，不把其中一个数组的完整性当作其它集合
完整性。冷态只读取所需族和有界实体，不因进入 L2 就预取另一事实族。

已有事实缓存继续使用批准的 365 天回溯边界、历史 24 小时 TTL 和包含今天窗口 90 秒 TTL。
字典安全投影使用 24 小时窗口，按当前租户、来源族、语义/结构版本和实体参数隔离。未授权的
普通用户子集不回填公共全厂事实底料键。

覆盖至少核对授权范围、原查询条件、窗口、粒度、必需列、语义参数和版本。完整年度、昨日及问题
整窗的选择沿用既有事实缓存解析器。服务端聚合不能倒推出缺失明细维度。生成时间只表示取得
快照的时刻，不表示客户数据已更新到该时刻，也不声称跨 API 存在客户事务快照。

完整性由适用 total、行数、集合关系、字段和有界分页校验证明。footer 缺失或不适用不能称为
对账通过。影子验证不一致时丢弃相关缓存证据并使用获准实时路径；回源不足或字段仍不成立时
相关分析不可用。持续身份/范围变化停止旧 interaction，不能继续使用旧句柄。

缓存 TTL 到期不会修改已取得的短生命周期授权快照；它只在本 interaction 的 deadline 内有效。
持久快照和 interaction 句柄均不延长原保留期。具体查询结果仍回显可见范围，`mes_filtered`
不能被转换为“全厂完整”。

## 8. 安全观察与事件

`ApprovedObservation` 只含下列白名单：状态、不透明数据/结果/知识引用、批准数据描述、批准知识
片段、行数、缺失字段、完整性、来源类别和安全原因码。数据描述可说明敏感字段存在，不返回敏感
字段实例。个人身份、个人报工/工资行、单价、原始样本、凭据、客户异常与任意 metadata 不进入
规划器、日志、trace 或展示事件。

| `state` / `source` | 含义 |
| --- | --- |
| `interaction_reuse` / `interaction` | 复用本轮已取得授权视图，不再回源 |
| `cache_hit` / `cache` | 持久缓存足以提供本次获准视图 |
| `live_fetch` / `upstream` | 有界回源后取得验证视图 |
| `empty` | 已证明完整的真实空集，仍带授权句柄 |
| `incomplete`、`unavailable` | 完整性、来源、字段或确认口径不足；不产生可提交完整合计 |
| `analyzed` | 已登记的宿主结果引用 |
| `knowledge` / `knowledge` | 已审核知识，无法作为当前工厂实例列表 |

规划通过现有逻辑模型别名和 LiteLLM 网关完成，计量阶段为 `PLAN`，修复为 `REPAIR`。
展示进度与模型观察分别处理；模型推理文本不承担业务决策。安全计量记录规划、工具、分析、
请求、页数、行数、token、句柄复用和缓存来源等计数，不登记原问题或原始工具参数。

非权威观测回调失败只作安全分类告警，不改变授权和业务终态。业务结果仍按原 interaction
持久化语义提交。token 获取/续期、字典冷态、事实回源和 shadow 属不同来源分类；衡量热态零业务
回源时，不把目录冷态或 shadow 测量混入收益样本。

## 9. 共享预算与生命周期

由 `InteractionRunExecutor` 保持唯一交互控制和终态权。L1、L2 及宿主取数使用同一个
`RunControl` 和单调时钟 deadline；切入 L2 只能收紧限制，不重置已消耗的模型、请求、页数或行数。
年度预取的独立较大预算不能由普通 L2 借用。

core 默认上限如下；宿主根据现有配置提供实际行数、页数和单次超时，且只能在继承预算上进一步
收紧。它们是执行上限，不是性能、命中率或客户容量承诺。

| 累计资源 | core 默认上限 |
| --- | --- |
| 模型轮次 | 12，含语义修复调用 |
| 语义修复 | 全 interaction 最多 1 次；可配置为 0 禁止修复 |
| 工具步骤 | 16 |
| 实际上游尝试 | 20，含适用 token 与业务调用尝试 |
| 业务请求/页 | 20；宿主分页消耗同一计数，不按工具重置 |
| 处理行数 | 50000；宿主可按普通请求已批准配置设置，载入和扫描累计计量 |
| 分析次数 | 6 |
| 模型 token | 30000 |
| 结果及安全观察字节 | 1048576 |
| 并发调用 | 1 |
| 单次调用 | 30 秒，并同时受整体 deadline 限制 |
| 相同动作与观察无进展 | 新结果出现前，最多 2 次；随后停止 |

模型调用和每个工具前后均检查取消、身份有效性与 deadline；网络分页、重试和局部分析消耗同一
累计预算。句柄复用不再次消耗上游请求，但新分析仍消耗计算和扫描预算。宿主结构化修复在调用前
消耗共享 `semantic_repairs`；规划修复由 core 消耗同一资源，二者不重复计费。初始解析已经修复
一次时，后续 L2 不再获得修复机会；创建新 Agent 或切换阶段都不重置计数。非法动作不形成无限
试错路径。

SSE 断线不取消业务执行。显式取消、超时、失败和完成后不得继续调用模型或 MES；计算工作线程
必须收束后才能关闭唯一 DuckDB 连接，随后销毁本 interaction 的句柄和结果引用。

## 10. 可用结局与不可用边界

| 结局 | 交付 |
| --- | --- |
| 可回答 | 验证的结果卡片或批准知识引用 |
| 需要条件 | 澄清，不把未指定事实时间默认为全历史 |
| 无权限 / 活动身份失效 | 拒绝，禁止相关业务取数 |
| 来源或口径不可用 | 明确不可用，不反复请求同一接口猜测 |
| 完整空集 | 说明当前窗口/范围无匹配，保留完整性和范围 |
| 不完整、预算、无进展 | 保持批准的停止分类，不伪造完整合计 |
| 取消 / 超时 / 执行失败 | 关闭交互资源，按既有终态事件返回安全原因 |

当前不可用集合包括：两族事实的跨族 JOIN、多对多与未验证关联、自由 SQL/代码/外部访问、
模型自创指标、没有确认来源的独立成衣完工数、无时间锚的待审核事实、没有授权实体来源的制单
配置、未能校验完整集合的配置计数、以档案年份桶推断款式品类，以及以工序或类型名称猜稳定编码。
