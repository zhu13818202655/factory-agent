# 客户 MES API 前置条件

> 本文定义系统可实施的技术底线。已发送客户、截至 2026-08-21 尚未答复的具体问题见
> [`customer-confirmation-questionnaire.md`](customer-confirmation-questionnaire.md)。问题本身不代表客户承诺；
> 收到正式答复后先记录证据，再更新本文和对应产品规则。

## 身份与组织

| ID | 能力 | 必须提供 |
|---|---|---|
| A1 | 当前用户 | `user_id`、`tenant_id`、`employee_id`、角色和所属组织 |
| A2 | 组织树 | 车间、小组、员工 ID、名称、上下级和有效期 |
| A3 | 管辖范围 | 管理者可见的车间、小组和员工 ID，或可推导该闭包的关系 |

## 业务资源

| ID | 资源 | 必须支持的筛选/关联 |
|---|---|---|
| C1 | 计件报工明细 | 时间、员工、部门、订单、款号、工序及所有关联 ID |
| C2 | 员工档案 | 批量员工/部门 ID、组织关系、在册状态和有效期 |
| C3 | 组织架构 | `dept_id`、`parent_id`、类型、名称和有效期 |
| C4 | 订单 | 时间、批量订单号、状态、`order_id`、`style_id`、交期 |
| C5 | 款号/款式 | 批量 `style_id`、款号和关键词 |
| C6 | 工序与工价 | 订单/款号批量筛选、工序 ID、顺序和有效工价 |
| C7 | 计划/排产 | 部门、款号、周期和计划量 |
| C8 | 工资结算 | 时间、员工、部门、金额和结算状态 |

C1~C8 是当前 Canonical 设计输入，不是对客户真实字段名的假设。客户可提供不同接口形态，
但必须能通过 Adapter 无损映射到相同领域数据。

## 可组合性硬要求

1. 返回稳定关联 ID，不能仅靠姓名、款号文本或组织名称 JOIN。
2. 支持批量 ID，禁止只能逐条查询造成无界 N+1。
3. 支持按授权 `dept_ids`/`employee_ids` 过滤，避免先全量拉取再过滤。
4. 列表响应提供 `items`、`total`、`page`、`size`，可证明已经拉全。
5. 支持统一时区的时间区间过滤，并明确边界是否闭合。
6. 所有调用只读、幂等、可超时，并提供稳定错误码和 `Retry-After`。
7. 提供字段字典、枚举、分页上限、限流策略和脱敏响应样例。

## 客户交付包

- 版本化 OpenAPI 或等价接口文档。
- 字段与枚举字典、关联关系和业务口径。
- 脱敏请求/响应样例以及可访问测试环境。
- 身份与权限说明、测试账号和数据范围样例。
- 数据量级、限流、超时、分页和变更通知机制。

真实材料到达后归档到 `contracts/customer/<version>/`，先生成差异报告，再实施
`CustomerMesAdapterV1`。不得直接把客户字段传播到 capability 或领域层。
