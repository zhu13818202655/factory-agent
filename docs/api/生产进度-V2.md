# 缝制生产进度 V2 接口调试文档

> 合并原「缝制生产进度 / 缝制生产进度详情 / 工序进度查询」三个接口，支持动态分组 / 动态聚合


---

## 一、接口基本信息

| 项 | 值 |
|---|---|
| 请求方式 | `POST` |
| 接口地址 | `{host}/api/NetYf/Sclzd/v2/ScjdQuery` |
| Content-Type | `application/json` |

---

## 二、权限说明

| 角色代码 | 角色 | 数据范围 |
|---|---|---|
| `00` | 员工 | **禁止查询**，返回无权限错误 |
| `01` | 组长 | 仅看本部门|
| `02` | 管理 | 看配置的部门范围 |
| 其他 / 管理员 | 全部 | 不受部门限制 |

权限过滤基于扫码记录 （员工扫码时所属部门）。

## 三、请求参数

### 3.1 基础参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `app_key` | string | 是 | 
| `dates` | DateTime | 是 | 开始日期（流程卡制单日期） |
| `datee` | DateTime | 是 | 结束日期（流程卡制单日期） |


### 3.2 过滤参数

| 字段 | 类型 | 匹配方式 | 说明 |
|---|---|---|---|
| `dh` | string | 等值 | 制单号 |
| `jhdh` | string | 等值 | 计划号 / 订单号 |
| `chuanghao` | string  | 模糊 | 床号 |
| `huohao` | string | 等值 | 货号编码 |
| `bbreed` | string | 等值 | 货号名称 |
| `worktype` | string | 等值 | 工序编码 |
| `wtname` | string | 等值 | 工序名称 |
| `color` | string | 模糊 | 颜色 |
| `chima` | string | 模糊 | 尺码 |
| `uid` | string | 等值 | 员工工号（扫码员工） |
| `dept` | string | 等值 | 部门编码（扫码员工所属部门） |


### 3.3 动态分组参数 `groupbyFields`

- 类型：`List<string>`
- 作用：决定输出列集合、列顺序、行排序优先级（默认按分组字段升序）
- 不传或传空：使用默认明细分组（全字段，等效原「详情+工序」合并视图）
- 重复字段自动去重；编码列与名称列属同一维度（如 `huohao` + `bbreed`），同时传入只分组一次、输出两列

默认明细返回制单日期字段 `rq`，该字段已由需求方在真实接口实测成功。
**返回 `rq` 不等于已确认它可以放进 `groupbyFields`**；当前仍使用下表已审核分组字段，不追加
未经确认的日期分组。默认明细加工到制单视图时，仅在同一制单内日期唯一且完整时保留该日期。

**可选分组字段：**

| 字段 | 说明 |
|---|---|
| `dh` | 制单号 |
| `jhdh`|  计划号 / 订单号（两者等价） |
| `chuanghao` | 床号 |
| `huohao` | 货号编码 |
| `bbreed` | 货号名称 |
| `worktype` | 工序编码 |
| `wtname` | 工序名称 |
| `color` | 颜色 |
| `chima` | 尺码 |
| `baohao` |  包号 |
| `userid` | 流程卡物料编号 |
| `fhsl` | 发卡数量 |
| `sssl` | 实收数量 |
| `uid` | 员工工号 |
| `uname` | 员工姓名 |
| `dept` | 部门编码 |
| `deptname` | 部门名称 |
| `wsort` | 工序排序号 |
| `zhgx` | 最后工序 1 代表最后工序 |

### 3.4 排序参数  `orderbyFields`

| 字段 | 类型 | 说明 |
|---|---|---|
| `orderbyFields` | List<string> | 每项格式 `"字段"` 或 `"字段:asc\|desc"`，按传入顺序决定优先级 |
| `orderByType` | string | 全局排序方向：`asc`（默认）/ `desc`，作用于未单独指定方向的项 |

- 可选排序字段 = 所有分组输出列 + 聚合输出列 + `wcl` / `bgs` / `bts`
- 不传时：自定义分组按分组字段顺序升序；默认明细分组按 `chuanghao → huohao → worktype` 升序
- 传入不存在的字段返回明确错误提示

## 四、完成率 wcl 计算口径

完工率统一为「实收数量 / 发卡数量」，不随分组维度变化，无需调用方手动指定。

```
wcl = sssl / fhsl × 100
```

- 分子 `sssl` = 实收数量
- 分母 `fhsl` = 发卡数量
- 分母为 0 时 wcl 返回 0，避免除零
- 保留 2 位小数

**说明**：`bgs`（已完工包数）/ `bts`（总包数）在纯制单级分组时仍额外输出，仅作为包维度的参考统计，暂不参与 wcl 计算；`wgs` （已完工工序数（已扫码））/ `wts`（总工序数） 亦仅为工序维度的参考统计，暂不参与 wcl 计算。

## 五、响应结构

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "list": [
      {
        "dh": "制单号",
        "rq": "2026-09-01",
        "chuanghao": "床号",
        "huohao": "货号编码",
        "bbreed": "货号名称",
        "bs": 15,
        "fhsl": 825,
        "sssl": 800,
        "zpsl": 300,
        "wgs": 10,
        "wts": 15,
        "wcl": 96.97
      }
    ],
    "total": 1,
    "footer": {
      "bs_total": 15,
      "fhsl_total": 825,
      "sssl_total": 800,
      "zpsl_total": 300,
      "wgs_total": 10,
      "wts_total": 15,
      "wcl_total": 96.97
    }
  }
}
```

### 5.1 list 行字段

- 分组字段：按 `groupbyFields` 传入顺序输出
- `rq`：制单日期，默认明细返回已实测成功，是缓存时间切片与制单日期展示的来源；`dh` 仅作制单标识，不能根据其前 8 位推日期
- `wcl`：完工率，口径统一 = 实收/发卡
- 纯制单级分组额外输出 `bgs` / `bts`（包统计参考，不参与 wcl）

需求方尚未给出 `rq` 的实际字符串格式。上面的日期仅为标准格式示例，不作为客户日期格式已确认
的证据。智能体支持 ISO 日期和合法 ISO 日期时间，取 `rq` 自身的业务日历日期部分并标准化为
`YYYY-MM-DD`；该字段不是时间点，不根据时区偏移移动到另一日期。缺失或非法日期不能回退到
制单号、不能跳过坏行后宣称完整；公共日期缓存拒绝
写入，实时数据仍无法验证时明确不可用或失败。相关缓存契约见
[V2 取数与缓存方案 §4.4](../design/V2接口取数重构与缓存加速方案.md#44-加工层与时间锚)。

实时原生分组包含 `dh` 且需要制单日期时，若响应缺少 `rq`，智能体在相同授权、窗口与业务条件下
有界回退到不传 `groupbyFields` 的默认明细，以可信 `rq` 生成受审视图；该路径额外增加一次真实
源取数并计量，不能当缓存热命中。默认明细仍缺少或返回非法 `rq` 时按 `upstream_invalid` 拒绝，
不进入缓存，绝不以 `dh` 补日期。原生分组正常返回 `rq` 时保持原生路径，供独立结果对照。
这项回退是智能体加工边界，不代表客户已确认 `rq` 可作为请求分组字段。

### 5.2 footer 合计

- 只对 `sum` / `count` 类型的聚合列做合计，输出为 `{列名}_total`
- `wcl_total` = `sssl_total / fhsl_total × 100`（不是各行 wcl 的平均）

## 六、调用示例

### 6.1 明细查询（等效原详情+工序合并，指定制单号）

```json
{
  "app_key": "xxx",
  "timestamp": 123,
  "sign": "xxx",
  "dates": "2026-09-01",
  "datee": "2026-09-30",
  "dh": "ZD202609001"
}
```
- 不传 groupbyFields → 默认全字段明细分组
- wcl = 实收/发卡
- 包含未扫码工序行（uid/uname 为 null，wgs=0）

### 6.2 按制单汇总

```json
{
  "app_key": "xxx",
  "timestamp": 123,
  "sign": "xxx",
  "dates": "2026-09-01",
  "datee": "2026-09-30",
  "groupbyFields": ["dh", "jhdh", "chuanghao", "huohao", "bbreed"],
  "orderbyFields": ["wcl:desc"]
}
```
- 纯制单级字段 → 额外输出 bgs / bts（包统计参考）
- wcl 统一 = 实收/发卡
- 按完工率降序

### 6.3 按部门汇总

```json
{
  "app_key": "xxx",
  "timestamp": 123,
  "sign": "xxx",
  "dates": "2026-09-01",
  "datee": "2026-09-30",
  "groupbyFields": ["dept", "deptname"],
  "orderbyFields": ["zpsl:desc"]
}
```
- 01/02 角色自动收窄到权限范围内的部门
- wcl 统一 = 实收/发卡

### 6.4 按货号汇总

```json
{
  "app_key": "xxx",
  "timestamp": 123,
  "sign": "xxx",
  "dates": "2026-09-01",
  "datee": "2026-09-30",
  "groupbyFields": ["huohao", "bbreed"]
}
```
- wcl 统一 = 实收/发卡

### 6.5 按部门+货号汇总

```json
{
  "app_key": "xxx",
  "timestamp": 123,
  "sign": "xxx",
  "dates": "2026-09-01",
  "datee": "2026-09-30",
  "groupbyFields": ["dept", "deptname", "huohao", "bbreed"]
}
```
- 每行 = 某部门在某货号上的完工进度
- wcl 统一 = 实收/发卡

### 6.6 按员工汇总（指定部门）

```json
{
  "app_key": "xxx",
  "timestamp": 123,
  "sign": "xxx",
  "dates": "2026-09-01",
  "datee": "2026-09-30",
  "dept": "D001",
  "groupbyFields": ["uid", "uname", "dept", "deptname"],
  "orderbyFields": ["zpsl:desc"]
}
```
