# `interaction.thinking` 推理原文事件 · 数据结构与对接契约

> **用途**：定义「推理原文」（模型思考过程）从后端到前端的传输契约，供后端据此实现、前端据此消费。
> **版本**：v1.1（2026-09-21）—— v1.0 契约本体不变，新增 §11「后端实现状态」
> **权威关系**：本文是 `docs/对接api文档.md` §5「SSE 事件」的前向兼容扩展 —— 该文档 §5.1 已声明「事件名集合此后仍可能扩充，前端必须忽略无法识别的 `event` 值」。`interaction.thinking` 为新增事件，**不修改任何既有事件与字段**。
> **消费方行为**：默认折叠隐藏，提供开关展开；**所有角色一致，不做权限区分**。

---

## 1. 链路总览

```
POST /v1/sessions/{session_id}/interactions      → 201 { interaction_id }
                ↓
GET  /v1/interactions/{interaction_id}/stream    → SSE
                ↓
   started → progress → [thinking × N] → [thinking(done)] → phase → result → completed
                ↓
GET  /v1/sessions/{session_id}/messages          → 历史回放（含 thinking 消息）
```

推理原文有**两条链路**，两者必须内容一致：

| 链路 | 载体 | 时机 | 是否必须 |
| --- | --- | --- | --- |
| 实时 | SSE 事件 `interaction.thinking` | 本轮执行过程中 | **必须**（本次对接目标） |
| 持久化 | `messages` 接口中 `kind="thinking"` 的消息 | 刷新/重开面板恢复聊天 | 可选，但推荐。缺失则刷新后推理消失 |

## 2. 数据结构层级与嵌套关系

```
interaction.thinking 事件
└── data : object                      （扁平，无嵌套；SSE 帧内单行 JSON）
    ├── text        : string   条件必填
    ├── seq         : integer  必填
    ├── done        : boolean  条件必填
    ├── elapsed_ms  : integer  可选
    └── truncated   : boolean  可选

SessionMessagesResponse                （持久化链路）
└── items : SessionMessage[]
    └── SessionMessage（kind = "thinking"）
        ├── message_id  : string   必填
        ├── role        : string   必填，固定 "assistant"
        ├── kind        : string   必填，固定 "thinking"
        ├── sequence    : integer  必填
        ├── text        : string   必填（拼接后的完整原文，非分片）
        └── elapsed_ms  : integer  可选
```

**注意**：与 `interaction.result` 不同，`thinking` 的 `data` **不含 `payload` 包装层**，所有字段平铺在 `data` 根上。

## 3. 实时链路：`interaction.thinking`

### 3.1 事件帧格式

一条事件一帧，帧间以**空行**分隔（与既有事件完全一致）：

```text
id: {sequence}
event: interaction.thinking
data: {单行 JSON}

```

### 3.2 `data` 字段定义

| 字段 | 类型 | 必填 | 取值范围 | 默认值 | 含义 |
| --- | --- | --- | --- | --- | --- |
| `text` | `string` | **条件必填**：非最后一片必填；最后一片可省略 | 单帧 1–200 字符；整轮累计 1–8000 字符 | 无 | 本片**推理原文增量**（delta），非全量。前端按到达顺序**拼接**。换行必须转义为 `\n` |
| `seq` | `integer` | **必填** | ≥ 1 的整数，同一轮内**严格递增、不跳号、不重复** | 无 | 分片序号。前端据此去重；缺号仅用于排查，不阻塞渲染 |
| `done` | `boolean` | **条件必填**：最后一片必须显式 `true`；非最后一片可省略 | `true` \| `false` | `false` | 是否为本轮推理的最后一片。收到 `true` 表示推理结束 |
| `elapsed_ms` | `integer` | 可选 | ≥ 0 | 无（前端自行计时） | 自本轮开始至今的**累计**思考耗时（毫秒）。与 `interaction.phase.duration_ms` 语义一致：累计值，非与上一片的间隔 |
| `truncated` | `boolean` | 可选 | `true` \| `false` | `false` | 后端因累计长度上限截断时为 `true`。仅最后一片需要携带 |

**字段约束细则**

- `text` 与 `done` 的合法组合只有三种，其余均视为非法帧：

| `text` | `done` | 是否合法 | 前端处理 |
| --- | --- | --- | --- |
| 非空 | 省略 / `false` | 合法 | 拼接并更新界面 |
| 空 / 省略 | `true` | 合法 | 标记推理结束（结束帧可不带 `text`） |
| 非空 | `true` | 合法 | 拼接后标记结束 |
| 空 / 省略 | 省略 / `false` | **非法** | 忽略该帧，不新建消息 |

- `seq` 起始值固定为 `1`，不允许从 `0` 开始。
- 同一轮内 `text` 的分片序号与 SSE 帧的 `id` 单调性一致：`seq` 越大的分片，其所在帧的 `id` 必须更大。

## 4. 持久化链路：`messages` 中的 thinking 消息

### 4.1 `SessionMessage` 字段定义（`kind = "thinking"`）

| 字段 | 类型 | 必填 | 取值范围 | 默认值 | 含义 |
| --- | --- | --- | --- | --- | --- |
| `message_id` | `string` | **必填** | 非空字符串，同一 session 内唯一 | 无 | 消息唯一标识 |
| `role` | `string` | **必填** | 固定 `"assistant"` | 无 | 消息角色 |
| `kind` | `string` | **必填** | 固定 `"thinking"` | 无 | 消息类型，新增枚举值 |
| `sequence` | `integer` | **必填** | ≥ 1，同一 session 内单调递增 | 无 | 消息在会话中的顺序号 |
| `text` | `string` | **必填** | 1–8000 字符 | 无 | **拼接后的完整推理原文**（非分片），换行以 `\n` 表示 |
| `elapsed_ms` | `integer` | 可选 | ≥ 0 | 无（缺失时前端不展示耗时） | 本轮累计思考耗时 |

- **不返回** `payload` 字段（`payload` 仅 `result_table` 消息使用）。
- 前端在 `restoreSession` 中**不会过滤** `kind="thinking"`（现有实现仅过滤 `kind="phase"`），因此刷新后思考块会按原样恢复并**默认折叠**。

## 6. 前端消费的数据结构（供后端对齐语义）

```ts
/** SSE 事件 data（新增事件的数据形态，扁平） */
interface InteractionThinkingData {
  text?: string
  seq: number
  done?: boolean
  elapsed_ms?: number
  truncated?: boolean
}

/** 消息类型枚举新增取值 */
type MsgKind =
  | 'plain_text'
  | 'clarification'
  | 'phase'
  | 'result_table'
  | 'error'
  | 'thinking'        // 新增

/** 聊天消息（思考过程以单条消息承载，分片续写同一条） */
interface ChatMessage {
  id: string
  role: 'user' | 'assistant' | 'system'
  kind: MsgKind
  text: string              // kind='thinking' 时为拼接后的完整原文
  time: string
  sequence?: number
  thinkingDone?: boolean    // 前端内部状态：推理是否结束
  thinkingElapsedMs?: number // 来自 elapsed_ms
}
```

## 7. 后端必须满足的约束

| # | 约束 | 说明与原因 |
| --- | --- | --- |
| 1 | `data` 必须是**单行 JSON** | 前端按行解析 SSE 帧。换行必须转义为 `\n`；若把真实换行写进 JSON，`JSON.parse` 失败并退化为 `{raw:"..."}`，界面显示原始文本 |
| 2 | `Content-Type: text/event-stream`，**不压缩、不缓冲** | Nginx 需 `proxy_buffering off`；不设 `Content-Length`；逐帧 flush，否则前端收不到实时流 |
| 3 | 每帧必须携带**独立且单调递增的 `id`** | `id` 是 durable 游标，`Last-Event-ID` 依赖它。**thinking 分片必须进入可重放事件日志**，否则断线重连后推理会缺段 |
| 4 | 任意 **40 秒**内必须有事件 | 前端读超时为 40s，静默超时即断连重连。长思考期间请持续发分片或穿插 `interaction.heartbeat` |
| 5 | 推理帧必须**早于** `interaction.result` | 前端收到 `result` 即收束本轮；此后再到的 `thinking` 会被丢弃 |
| 6 | 终态事件后关闭连接 | 终态为 `interaction.completed` / `failed` / `cancelled` |
| 7 | 重连幂等 | 重连只做事件跟随与重放，**不得重复执行取数与推理** |
| 8 | 所有分片发送完毕再发结束帧 | 结束帧（`done:true`）之后不得再发同一轮 `thinking`（除非是新的一轮） |
| 9 | 内容脱敏 | 推理原文会**对所有角色展示**，输出前需过滤系统提示词、内部字段名/表名、SQL、其他组织数据等敏感内容 |

## 8. 异常与边界场景

| # | 场景 | 期望行为（前端侧） | 后端需注意 |
| --- | --- | --- | --- |
| 1 | `done` 始终未下发 | 以 `interaction.result` / `completed` 作为兜底结束信号，不阻塞渲染 | 仍建议显式下发结束帧 |
| 2 | `text` 为空且 `done` 不为 `true` | 忽略该帧，不新建消息 | 避免发送空分片 |
| 3 | `seq` 重复 | 去重，仅保留首次出现的分片 | 保证严格递增 |
| 4 | `seq` 缺号（如 1,2,4） | 拼接不中断，界面正常；仅用于排查 | 尽量不跳号 |
| 5 | `seq` 乱序到达 | 按**到达顺序**拼接（SSE 本身有序）；不按 `seq` 重排 | 保证发送顺序与 `seq` 一致 |
| 6 | 超过 40s 无任何事件 | 断连并携带 `Last-Event-ID` 重连 | 持续分片或发心跳 |
| 7 | 重连后推理续传 | 若分片已入可重放日志，则无缝续传；否则可能出现段落缺口，前端容忍 | **推荐将 thinking 分片持久化到事件日志** |
| 8 | 累计长度超上限（8000 字符） | 保留已收内容，并提示「推理过程已截断」 | 截断后发 `done:true, truncated:true` |
| 9 | `result` 之后到达 thinking | **丢弃**（本轮已收束，不再新建消息） | 不要跨轮混发 |
| 10 | 用户取消（`cancelled`） | 已收推理**保留并折叠**，不删除 | 已发出的分片无需回收 |
| 11 | 本轮失败（`failed`） | 已收推理**保留并折叠**，错误文案照常展示 | 保留已发出的思考内容便于排查 |
| 12 | 闲聊 / 追问轮次 | 有则展示，无则不展示，两者都支持 | 建议仅在含业务取数的轮次发送，避免噪音 |
| 13 | 多轮追问 | 每轮生成**独立**一条 thinking 消息，按 `sequence` 排序 | 每轮 `seq` 从 1 重新计数 |
| 14 | interaction 不存在 | 现有约定：返回**空事件流**（非 404），前端按失败处理 | 沿用既有实现 |
| 15 | `elapsed_ms` 缺失 | 不展示耗时，仅展示「思考过程」 | 可选字段，缺失不报错 |
| 16 | 未知事件名 | 忽略，不报错、不终止流（沿用 §5.1 前向兼容约定） | —— |

## 9. 前端消费行为（供后端对齐预期）

| 行为 | 说明 |
| --- | --- |
| 默认隐藏 | 折叠态仅显示一行「思考过程 · 12s」，**推理原文不可见** |
| 开关展开 | 点击该行展开/收起；**所有角色一致**，不做权限区分 |
| 流式期间 | 自动展开并滚动到底部；收到 `done:true` 或 `result` 后**自动折叠** |
| 渲染节流 | 前端按约 80ms 合并分片批量更新；后端**无需**为此降频 |
| 历史恢复 | `kind="thinking"` 消息保留并默认折叠 |
| 导出 | 推理原文**不进** xlsx 导出 |
| 全局开关 | 前端保留环境变量总开关，可一键关闭整块渲染；后端无需感知 |

**验收清单**

| # | 验证点 | 通过标准 |
| --- | --- | --- |
| 1 | 帧格式 | `event: interaction.thinking` 帧存在，`data` 为单行合法 JSON |
| 2 | 分片序号 | `seq` 从 1 起严格递增，无重复 |
| 3 | 结束标记 | 最后一个 thinking 帧携带 `done:true` |
| 4 | 顺序 | 所有 thinking 帧的 `id` 均**小于** `interaction.result` 的 `id` |
| 5 | 转义 | 文本中的换行在 JSON 内为 `\n`，非裸换行 |

| 7 | 续传 | 携带 `Last-Event-ID` 重连后，推理内容不缺失、不重复 |
| 8 | 持久化 | `messages` 接口返回 `kind="thinking"` 消息，`text` 为拼接后的完整原文 |
| 9 | 一致性 | 实时拼接结果与历史恢复的 `text` **逐字符一致** |
| 10 | 脱敏 | 抽样检查推理原文，无系统提示词、内部表名/字段名、其他组织数据 |

## 11. 后端实现状态（v1.1）

本节记录后端对该契约的**落地情况**，便于前端判断哪些行为已经可以依赖。契约本身（§1–§10）
不变；若实现与契约冲突，以契约为准并修实现。

### 11.1 实现位置

| 关注点 | 模块 | 说明 |
| --- | --- | --- |
| 门禁、合并、预算、行形 | `application/session/thinking.py` | 纯函数 + `ThinkingCoalescer`，不依赖会话时基，可单独测试 |
| 交错驱动（等待期内发帧） | `application/session/narration.py` | 旁白调用与业务步骤**并发**执行，步骤一结束即放弃旁白 |
| 帧发射与轮次收束 | `application/session/outcomes.py` | `_fact` / `_flush_frames` / `_close_transcript`；每个终止路径都先关轮次 |
| 事实句接线 | `application/session/pipeline.py` | 阶段句、查询标题、时间范围、可查询范围 |
| 分页进度通道 | `ports/mes_progress.py` | `ContextVar` 单任务作用域；`data_api` 发布、`application` 订阅 |
| 流式网关端口 | `ports/model.py` / `llm/router_gateway.py` | `ModelStreamGateway.stream()`；`ModelStage.THINKING` |
| 开关与限额 | `config.py` / `application/session/definitions.py` | 见 §11.5 |

### 11.2 分片的两个来源

一轮的 `text` 由**两部分拼成**，前端看到的是同一条流：

1. **模型自由生成的旁白**（真 token 流）。只覆盖两段等待：意图解析、业务取数。措辞自由，
   但**事实受限**——提示词只给「事实清单」（阶段名、能力中文标题、已解析的时间范围、调用者
   自己的可查询范围、取数分页计数），不含任何业务明细行。
2. **服务端已确定的事实句**。阶段进入、查询标题、时间范围、可查询范围、取数分页进度。
   这些不依赖模型，**是等待期的兜底与主体**。

因此：**即使部署的模型网关不支持流式，本事件仍然可用**（纯事实句）。此时不会为等待期额外
发起旁白调用，也就不会产生额外的模型费用；等待完全由事实句覆盖。

模型旁白只负责**措辞**，事实句负责**数据**。取数等待期用户看到的「已取回 N 行 / 共 M 行 /
第 K 页」一律来自分页器的**真实计数**，模型不参与生成这些数字；模型若自行提起任何 4 位以上
数字，会被门禁判为编造并丢弃（§11.3），因此旁白里不会出现未经服务端确认的业务数值。
前端的展现方式无需区分两来源。

### 11.3 门禁（脱敏，契约 §7-9）

- 每一片在发出前都要过 `rejection_reason`：命中内部标识符（能力编号、`snake_case` 步骤/列名）、
  SQL 关键字、`http(s)://`、凭据字段名、提示词字样、`yaml/json` 后缀等即**丢弃整片**。
- 校验对象是**本轮已接受的全文 + 新片**，而不是只看新片：否则一个被切开两片的标识符会各自
  通过。分片边界因此也**不会把一个 token 拦腰截断**。
- 命中后**放弃该来源**（本轮的模型旁白不再产出），而**不是改写原文**——改写过的句子可能反转
  自己的含义，风险高于静默。
- 模型提到的 **4 位及以上数字**必须出现在本轮事实清单里，否则判为编造并丢弃。

### 11.4 与契约条目的对应

| 契约条目 | 实现方式 |
| --- | --- |
| §3.2 单帧 ≤200 字符 | 合并阈值 120 字符触发发送；单帧上限 200 |
| §3.2 整轮 ≤8000 字符 | 超限即停止产片，最后一片带 `truncated:true` |
| §3.2 `seq` 从 1 严格递增 | 计数器每轮重置；与帧 `id:` 各自独立（`id:` 是全局持久游标） |
| §3.2 `done` 收尾 | 收束时补发 `text:""`+`done:true`，之后本轮不再有分片 |
| §3.3 行形 | 由服务端写出的每一句（事实句）都以换行开头，因此不会插进模型句子的中间。模型自己的分片按原样拼接，换行与否取决于模型输出（提示词要求它一句一行） |
| §7-3 进可重放日志 | 每片都是一条持久事件，断线重连按 `Last-Event-ID` 重放 |
| §7-5 早于 `result` | 所有终止路径（正常/追问/闲聊/取消/失败）都**先收束轮次**再分配终止事件序号 |
| §7-8 分片发完再发结束帧 | 轮次收束是一次性的：重复进入不会发出第二个 `done` |
| §7-9 内容脱敏 | 见 §11.3 |
| §4 持久化 | 仅当本轮确实产出了内容时，才写入**一条** `kind="thinking"` 消息，`text` 为拼接全文，`payload={"elapsed_ms":…}`；它的 `sequence` 复用最后一片的事件号 |

### 11.5 配置开关（服务端）

| 配置项 | 默认 | 作用 |
| --- | --- | --- |
| `session_thinking_enabled` | `true` | 关闭后**整轮不发** `interaction.thinking`，也不写 `kind="thinking"` 消息 |
| `session_thinking_timeout_seconds` | `20.0` | 单次旁白调用上限；超时即放弃，**绝不因此让回答变慢** |
| `session_thinking_tick_seconds` | `0.25` | 等待期检查并冲刷分片的间隔，决定分页进度最晚出现的时间 |
| `session_thinking_max_output_tokens` | `160` | 单次旁白调用的输出上限（旁白是短句，非全文） |
| `llm_thinking_stream_alias` | `factory-fast` | 旁白走独立别名，不与其所描述的调用争抢同一部署 |

旁白调用按 `ModelStage.THINKING` **正常计入用量**，失败也计（失败仍是花费）。
