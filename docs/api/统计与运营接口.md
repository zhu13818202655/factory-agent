## 0. 相对上一版的四处破坏性变更（前端必读）

本版把原独立服务的接口并入主服务，并收敛了工厂选择器的出参；只有**四处**有意变更；其余路径、
字段名、状态码与错误语义逐一致。

| # | 变更 | 说明 |
|---|---|---|
| ① | 前缀 `/admin/v1` → `/v1/statistics` | 全量替换，**不保留旧路径别名**，一次性切换 |
| ② | 列表 / 详情出参新增 `tenant_ref` | 非密短句柄，用于一切运营操作寻址；`app_key` 仍脱敏 |
| ③ | 租户管理端点路径参数 `{app_key}` → `{tenant_ref}` | 见 §5.1。**请删掉前端「记住明文 AppKey」那套逻辑** |
| ④ | `GET /tenants` 出参由**明文 AppKey 列表**改为 `[{tenant_ref, tenant_name}]`；工厂筛选参数 `app_key` → `tenant_ref`，并**从 `by-tenant` 铺到全部聚合端点** | 见 §5.2.1 / §5.2.8。**`by-tenant?app_key=` 现在会返回 422**（不静默忽略，避免旧客户端以为自己筛过了）；`GET /tenants` 里的 `app_key` 字段**已彻底移除**，不要再读。`summary`/`timeseries`/`dimensions`/`users`/`mes-*`/`models`/`capabilities`/`errors` 这 10 个端点新增同名可选参数 `tenant_ref`（原来只有 `by-tenant` 能按工厂筛） |

基地址：不再有独立服务的端口，改为主服务地址（不再是 `:8020`）。
健康检查也不再分两套：统一用 `GET /health/live` 与 `GET /health/ready`。

## 2. 鉴权（必读）

统计面自建平台运营账号体系，采用 **Bearer Token 认证**（D16）。**这是统计面的唯一鉴权
通道**——原「可信网关注入三 header」的直连通道已删除。**请求体 / URL 一律不得携带身份。**

### 2.1 认证方式

| 方式 | 说明 | 场景 |
|---|---|---|
| `Authorization: Bearer <token>` | token 由 `/v1/statistics/auth/login` 签发，或由 `FACTORY_AGENT_STATISTICS_API_TOKEN` 配置下发（映射到 `admin` 角色） | 前端调用、内部运营调用 |

前端对接（D16）：使用平台下发的 `FACTORY_AGENT_STATISTICS_API_TOKEN`，在请求头携带
`Authorization: Bearer <token>` 即可调用全部接口，**不需要实现注册 / 登录**。该 token 同时是
清库后引导首个运营账号的唯一通道，请单独保管。

内部运营：通过注册 / 登录接口获取 token 后调用。

### 2.1.1 与业务接口互不越权

统计面与业务问答是**两个独立身份域**，都不接受对方的凭证：

| 凭证 | 统计面 `/v1/statistics/*` | 业务路由 `/v1/*` |
|---|---|---|
| 平台 Bearer token | ✅ | ❌ |
| 工厂凭证（`X-Factory-Credential`） | ❌ | ✅ |

前端不得假设「同一个 token 两边通用」。

### 2.2 角色

| 角色 | 读用量 | 看用户级明细 | 导出 | 工厂账户（读） | 工厂账户（写） | 运营账号管理 |
|---|---|---|---|---|---|---|
| `viewer` | ✅ | ✅ | ❌ | ✅ | ❌ | ❌ |
| `analyst` | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ |
| `admin` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |

越权行为返回 `403`。token 中携带 `principal_id` / `role` / 可看租户集合；租户集合为空表示
平台全部租户，非空则仅可访问列出的 AppKey。

## 3. 通用约定

### 3.1 时间

- 所有查询接口必须带 `start` 与 `end`，ISO 8601 格式（推荐 UTC，`2026-08-01T00:00:00Z`），`start` 必须在 `end` 之前；
- 最大时间跨度 366 天；超过返回 `422`；
- 响应中的时间为 UTC，`timezone` 字段标注展示时区（默认 `Asia/Shanghai`）。

### 3.2 分页

- 涉及列表的接口统一使用 `limit` / `offset`；
- `limit` 默认见各接口说明，上限 `200`，超过会截断（不报错）。

### 3.3 错误

统一使用 HTTP 状态码 + `{"detail": "..."}`：

| 状态码 | 含义 |
|---|---|
| `400` | 请求不合法（仅个别接口） |
| `403` | 缺 Bearer token / 角色不足 / 租户越权（含 `PlatformScope` 过滤） |
| `404` | 资源不存在（如导出记录、租户句柄不存在） |
| `422` | 参数校验失败（时间不合法、跨度超限、维度不支持等） |

### 3.4 响应元字段

用量类响应统一携带以下字段，前端**不得把不完整结果当作完整结果展示**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `metric_version` | string | 指标口径版本（`rollup=...;contract=...;p=...`），口径变更后字段格式不变但值变化 |
| `timezone` | string | 展示时区 |
| `incomplete` | bool | `true` 表示**汇总落后于原始事实**（rollup 最新重算时间早于事实新鲜度减去容差，通常意味重算任务停摆或某窗口未重算）；窗口内本就无事实时不算不完整（那是「无使用」）。前端应提示「数据不完整」 |
| `freshness` | datetime\|null | 数据最新统计时间（仅 summary） |

### 3.5 AppKey 与 `tenant_ref`

- **AppKey 是客户 MES 密钥**。除「新增账户」的响应外，所有出参中的 AppKey 一律为
  **前 6 位 + `***`**（如 `fac-01***`），前端不得要求接口返回明文；
- 新增账户时明文 AppKey 仅返回一次，前端应提示运营人员保存；
- **一切运营操作按 `tenant_ref` 寻址**：它是非密的短随机串（如 `t_7f3a9c21`），列表与详情
  出参都会返回，不需要脱敏，也不可从 AppKey 推导。租户管理端点的路径参数就是它；
- **按工厂筛选用量一律传 `tenant_ref`**：所有 `usage/*` 聚合端点都接受同一个可选参数
  `tenant_ref=`（`by-tenant` 另有 `name=` 做工厂名模糊匹配）。**没有任何接口接受明文 AppKey
  作为查询参数**——旧参数 `by-tenant?app_key=` 会直接返回 `422`，提示改用 `tenant_ref`
  （宁可报错，也不静默忽略，否则旧客户端会以为自己筛过了）；
- 为什么不用 AppKey 拼管理路径：脱敏值是有损截断、无法还原；而**首见自动登记的租户从未
  经过「新增账户」接口**，运营根本拿不到它的明文 AppKey（详见 §4.4）。

### 4.4 租户生命周期（理解 §5.1 的前提）

租户（工厂账户）不是必须先「新增」才能使用。生命周期如下：

1. **首见自动登记**：客户 MES 凭证交换成功的那一刻，服务端即把该 AppKey 登记进
   `tenant_registry`（幂等 upsert），状态为 `active`，并生成 `tenant_ref` 与占位名
   `未命名工厂-<ref 前 6 位>`。此过程对前端**透明且无接口**——运营会看到列表里多出一个
   「未命名工厂-xxx」，改名即可。
2. **默认启用**：登记即 `active`，不需要人工开通（`registration_mode=auto`）。
3. **停用即拒绝问答**：`DELETE` 后该租户的业务请求一律 `403`，`detail` 为稳定标识
   `tenant_disabled`（业务接口文案由业务前端负责）。停用**不会**删除任何历史数据。
4. **停用不影响统计面**：被停用的租户仍可在本接口查询其历史用量与审计——平台运营必须能
   对账。
5. **寻址一律用 `tenant_ref`**：自动登记的租户没有「新增账户」响应，运营看不到它的明文
   AppKey，因此改名 / 停用 / 启用都只能按 `tenant_ref` 做。

登记失败不会影响问答（fail-open + 告警）：本地账本写失败只是「少记一笔」，客户 MES 的
凭证交换才是权威。

## 5. 接口明细

> 以下示例为约定响应结构；`start`/`end` 均省略。所有请求需带 §2 的
> `Authorization: Bearer <token>`。

### 5.1 工厂账户管理

#### 5.1.1 账户列表

```
GET /v1/statistics/tenants/registry?limit=20&offset=0
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `limit` | int | 否 | 每页条数，默认 20，上限 200 |
| `offset` | int | 否 | 偏移，默认 0 |

响应 `200`：

```json
{
  "items": [
    {
      "tenant_ref": "t_7f3a9c21",
      "app_key": "fac-01***",
      "tenant_name": "温州制衣一厂",
      "status": "active",
      "created_at": "2026-07-02T00:00:00Z",
      "updated_at": "2026-08-28T02:30:00Z"
    }
  ],
  "total": 3,
  "next_cursor": 20,
  "timezone": "Asia/Shanghai"
}
```

字段说明：

- `tenant_ref`：**非密唯一句柄**，后续所有租户操作（详情 / 编辑 / 停用 / 启用）的路径参数。
  新增字段（见 §0 变更 ②），前端不要再缓存明文 AppKey。
- `status` 取值 `active`（启用）/ `disabled`（停用）；
- `app_key` 已脱敏，**不可用于寻址**；
- `next_cursor` 为下一页 `offset`，为 `null` 表示无更多。它按「已扫描行数」推进，与 `total`
  同口径；存在 `PlatformScope` 租户过滤时，返回的 `items` 可能少于 `limit`，这是正常的
  （被过滤掉的行不返回），按 `next_cursor` 翻页即可，**不要**用 `items.length` 推断是否还有
  下一页。

#### 5.1.2 账户详情

```
GET /v1/statistics/tenants/registry/{tenant_ref}
```

| 参数 | 说明 |
|---|---|
| `tenant_ref` | 租户句柄，取自列表 / 详情 / 创建响应 |

响应 `200`：同列表单项（含 `tenant_ref`、`tenant_name`、`status`、`created_at`、
`updated_at`；`app_key` 脱敏）。`404`：句柄不存在。

#### 5.1.3 新增账户

```
POST /v1/statistics/tenants/registry
```

请求体：

```json
{
  "tenant_name": "新工厂名称",
  "status": "active"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `tenant_name` | string | 是 | 工厂 / 企业全称 |
| `status` | string | 否 | `active`（默认）/ `disabled` |

响应 `201`（**仅此接口返回明文 AppKey，须由前端提示保存**；同时返回 `tenant_ref`）：

```json
{
  "tenant_ref": "t_7f3a9c21",
  "app_key": "fac-新生成的明文Key",
  "tenant_name": "新工厂名称",
  "status": "active",
  "created_at": "2026-08-29T10:00:00Z",
  "updated_at": "2026-08-29T10:00:00Z"
}
```

> 请求体的 `app_key` 为**选填**：留空时服务端随机生成，该 key 与客户 MES 分配的 AppKey
> 不一致，因此「停用」开关对它不会对真实调用生效（停用守卫按客户 MES 的 AppKey 匹配）。
> 对真实工厂请填入弘兆分配的 AppKey，或在首见自动登记后直接按 `tenant_ref` 操作。
>
> `tenant_ref` 由此接口一并返回，前端**只需保存它**用于后续寻址；明文 AppKey 只在需要接入
> 客户 MES 时交给客户/实施方。

#### 5.1.4 编辑账户

```
PATCH /v1/statistics/tenants/registry/{tenant_ref}
```

请求体（均为可选，至少传一个）：

```json
{
  "tenant_name": "更名后的工厂",
  "status": "disabled"
}
```

响应 `200`：更新后的账户（AppKey 脱敏）。`404`：账户不存在。

#### 5.1.5 停用账户（F2.4 删除按钮）

```
DELETE /v1/statistics/tenants/registry/{tenant_ref}
```

- 语义为**停用**：`status` 置 `disabled`，**不做物理删除**，历史用量与事件全部保留；
- 停用后该租户的**业务问答请求**一律 `403`（`detail` 为 `tenant_disabled`），不再发起新的
  MES 调用，也不消耗 LLM；已在跑的 interaction 允许跑完；
- 停用**不影响本接口**：历史用量、会话与导出仍可查询（§4.4 第 4 条）；
- 响应 `204`；句柄不存在返回 `404`。

#### 5.1.6 重新启用

```
POST /v1/statistics/tenants/registry/{tenant_ref}/enable
```

响应 `200`：更新后的账户（`status: "active"`，`app_key` 仍脱敏）。`404`：句柄不存在。

### 5.2 用量统计

> **统一的可选工厂过滤**：除 5.2.1（工厂选择器）与 5.2.8（本身就是按工厂分组）外，
> 本节**每一个** `usage/*` 端点都接受一个可选查询参数 `tenant_ref`（F1.3）：
>
> | 参数 | 类型 | 必填 | 说明 |
> |---|---|---|---|
> | `tenant_ref` | string | 否 | 按工厂精确筛选。传**非密句柄**（来自 5.2.1 的 `tenant_ref`），**不传 AppKey** |
>
> 语义三态：
> - **不传** → 按当前 token 的租户集合统计（平台级 token 即全平台）。
> - **传合法句柄** → 收窄到该工厂；若该工厂在窗口内没有数据，返回空结果（`tenant_ids` 为空、
>   计数为 0）——这是**真实答案**，不是错误。
> - **传未知句柄** → `422`（`unknown tenant_ref`）；**传超出 token 可见范围的句柄** → `403`
>   （筛选不能变成越权探测）。
>
> 响应里的 `tenant_ids` 始终是**脱敏** AppKey（`fac-01***`），用于让前端确认实际生效的租户集合。

#### 5.2.1 工厂选择器（✅ 现有，出参已收敛）

```
GET /v1/statistics/tenants?start=...&end=...
```

响应 `200`：

```json
[
  { "tenant_ref": "t_7f3a9c21", "tenant_name": "温州制衣一厂" },
  { "tenant_ref": "t_ac5d0e2f", "tenant_name": "未命名工厂-t_ac5d" }
]
```

为时间范围内有数据、且当前操作者获准查看的工厂；用于看板顶部「工厂」筛选下拉的初筛，
下拉的 `value` 传 `tenant_ref`、展示 `tenant_name`。

> **出参不含任何形式的 AppKey**（明文或脱敏都没有）：这个接口曾经返回明文 AppKey 列表，
> 等于让每个能看用量看板的人都拿到凭据；现在只回非密句柄与工厂名。
> 若某个租户在注册表里没有记录（因而没有可寻址的句柄），它会**从选择器中略去**，
> 而不是用 AppKey 兜底展示。

#### 5.2.2 总览 summary（✅ 现有）

```
GET /v1/statistics/usage/summary?start=...&end=...
```

响应 `200`：

```json
{
  "tenant_ids": ["fac-01***"],
  "start": "2026-08-01T00:00:00Z",
  "end": "2026-08-29T00:00:00Z",
```

### 5.3 导出

#### 5.3.1 创建导出

```
POST /v1/statistics/exports
```

请求体：

```json
{
  "start": "2026-08-01T00:00:00Z",
  "end": "2026-08-29T00:00:00Z",
  "format": "xlsx",
  "granularity": "day",
  "metrics": ["questions", "prompt_tokens", "completion_tokens", "mes_output", "mes_payroll", "mes_order", "mes_other"]
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `start` / `end` | datetime | 是 | 时间范围 |
| `format` | string | 否 | `csv` / `xlsx`，默认 `csv` |
| `granularity` | string | 否 | `hour` / `day`，默认按日 |
| `metrics` | string[] | 否 | 导出指标，支持新增 MES 分类指标 |

响应 `201`：

```json
{
  "export_id": "exp_xxx",
  "format": "xlsx",
  "status": "pending",
  "download_url": null,
  "expires_at": null,
  "created_at": "2026-08-29T10:00:00Z"
}
```

#### 5.3.2 查询导出状态

```
GET /v1/statistics/exports/{export_id}
```

响应 `200`：`download_url` 就绪后非空（短时签名链接）。

#### 5.3.3 下载

```
GET /v1/statistics/exports/{export_id}/download?token=...
```

`token` 为 5.3.2 返回的 `download_url` 中携带的签名参数；`Content-Disposition` 为附件下载。
`403`：链接失效或已过期。

## 6. 前端功能点 ↔ 接口对照

| 看板功能 | 接口 |
|---|---|
| F1.1 日期范围筛选 | 所有查询接口的 `start` / `end` |
| F1.2 按工厂名称 / ID 筛选 | `by-tenant?name=`（名称）/ `tenants`（下拉初筛，回 `tenant_ref`） |
| F1.3 按工厂精确筛选 | 任一 `usage/*` 端点带 `tenant_ref=`（`by-tenant` 上原 `app_key=` 已移除，传即 422） |
| F1.5 导出报表 | `POST /exports` + `GET /exports/{id}` + `download` |
| F1.6 总 Token 消耗 | `summary.tokens` 四项求和 |
| F1.7 智能体总查询次数 | `summary.questions` |
| F1.8~F1.10 三类接口调用 | `mes-categories.output / payroll / order` |
| F1.11 每日 Token 趋势 | `timeseries?granularity=day&metrics=prompt_tokens,...` |
| F1.12 接口类型分布饼图 | `mes-categories.categories`（四块） |
| F1.13 工厂明细表格 | `by-tenant` |
| F1.14 分页 | `by-tenant?limit&offset` |
| F2.1~F2.6 工厂账户配置 | `tenants/registry` 六个接口 |
