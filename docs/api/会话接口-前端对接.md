# 会话接口（历史会话 / 新建会话 / 会话详情）— 前端对接文档

本文档是给前端同事的**对接交付件**，描述 AI 助手新增的三个会话接口，用于替换当前
「会话只存在浏览器本地」的实现：

| 编号 | 方法与路径 | 用途 |
| --- | --- | --- |
| **C1** | `GET /v1/conversations` | 当前登录人的历史会话列表（分页，按最近活动倒序） |
| **C2** | `POST /v1/conversations` | 新建会话（幂等，可直接返回整个会话流） |
| **C3** | `GET /v1/conversations/{session_id}` | 会话详情：元信息 + 全部轮次 + 全部消息 |

- 状态：**已实现并上线可用**（后端已合并主体实现，含真实数据库集成测试）。
- 适用范围：PC 悬浮小助手与 App 端共用同一套接口。
- 与主文档的关系：通用约定（鉴权、错误码、SSE 等）见
  `docs/api/AI助手前端对接API文档.md`（下文简称「主文档」）；本文只描述会话这三个接口，
  编号 `C1`–`C3` 与主文档 §4.x 不冲突。**本文可独立交付，无需先读主文档也能完成对接**
  （鉴权等必要前置在 §1 复述）。
- 本期不做：会话删除（无 `DELETE` 接口），前端历史面板**不要**放删除入口。原因见 §8。

---

## 1. 对接前置（必读）

1. **鉴权**：所有请求都带请求头 `X-Factory-Credential`，值为**加密的 app_key**。
   服务端用它去客户 MES 换 accessToken，前端全程不接触 accessToken。
   降级联调环境（服务端未配 token 网关）改用 `X-Factory-Tenant-Id` + `X-Factory-User-Id`。
2. **身份只来自凭据**：请求体与 query **不含** `tenant_id` / `user_id` / 角色 / 数据范围字段，
   传了也会被忽略。**不需要**任何「查谁的历史」参数——就是「当前凭据这个人」的历史。
3. **会话归属** = `(租户, 用户, session_id)`。一个 AppKey 一个工厂，所以不存在跨租户查询。
4. **跨身份一律 `404`**：访问别人的 `session_id` 与「该会话不存在」返回完全相同的
   `404 {"detail": "conversation not found"}`，前端按「不存在」处理即可，**不要**试图区分。
5. **分页**：`limit` + `cursor`，响应带 `next_cursor`（`null` = 没有下一页）。
   `cursor` 是服务端签发的**不透明字符串**，前端只做原样回传，**不要解析、不要拼接、不要缓存复用**。
6. **时间**：带时区偏移的 ISO 8601 字符串（生产为 UTC，形如 `2026-09-21T02:15:31+00:00`）。
   前端用 `new Date(str)` 直接解析；**不要**做字符串截取、也不要在前端做日期换算。
7. **错误**：HTTP 错误统一 `{"detail": "..."}`；请求体结构校验失败为 FastAPI 标准
   `{"detail": [...]}`。
8. **无副作用**：C1 / C3 是纯读，不触发问答、不调用客户 MES、不消耗模型额度，可安全重试与并发。
   C2 只写会话元数据（不调 MES、不调模型、不产生用量计量）。
9. **租户停用**：租户被平台停用时，这三个接口在鉴权层直接返回
   `403 {"detail": "tenant_disabled"}`，不会执行任何读写。

## 2. 核心对象

### 2.1 ConversationSummary（会话摘要）

```json
{
  "session_id": "sess_2f1c9b748a3e4d6f9c216c1f0a7b5e10",
  "title": "我这个月的工资是多少",
  "created_at": "2026-09-21T02:15:31+00:00",
  "updated_at": "2026-09-21T02:18:04+00:00",
  "message_count": 7,
  "interaction_count": 2,
  "last_message": {
    "role": "assistant",
    "kind": "result_table",
    "text": "已返回 1 行结果。",
    "created_at": "2026-09-21T02:18:04+00:00"
  },
  "last_status": "completed"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `session_id` | string | 会话标识，即 C3 路径里的 `{session_id}` |
| `title` | string \| null | 会话标题。**服务端派生值，不可编辑**（规则见 §2.5）；`null` 时前端显示「新对话」 |
| `created_at` | string | 会话创建时间 |
| `updated_at` | string | 会话最近一次活动时间，**C1 列表按此字段倒序** |
| `message_count` | int | 持久化消息条数，**不含 `kind="phase"`**（过程行无回看价值，与前端渲染口径一致） |
| `interaction_count` | int | 该会话的轮次数；新建未提问的会话为 `0` |
| `last_message` | object \| null | 列表预览用的最后一条消息（`role` / `kind` / `text` / `created_at`）；空会话为 `null` |
| `last_status` | string \| null | 最近一轮的 `status`（取值见 §2.4）；空会话为 `null` |

> `last_message.text` 是服务端裁剪过的**预览文本**（最长 200 字符，超出截断补 `…`）；
> 完整正文请从 C3 的 `messages` 取。
>
> `last_message` 是会话里**最新一条非 `phase` 消息**，所以它的 `kind` 可能是 `thinking`
> （该轮推理原文）。列表预览时建议：`kind === 'thinking'` 就显示「思考过程」类占位文案，
> **不要**把推理原文当成会话摘要展示。
>
> `last_message` 只用于列表一行预览，**不能**当作消息列表使用。它包含的内容就是用户本人
> 会话里的内容（含用户自己输入的问句），不引入额外数据暴露。

### 2.2 ConversationTurn（轮次）

```json
{
  "interaction_id": "it_7d3a1c20",
  "status": "completed",
  "state": "answered",
  "capability_id": "fr002_own_wage",
  "created_at": "2026-09-21T02:15:31+00:00",
  "completed_at": "2026-09-21T02:15:33+00:00",
  "error_category": null
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `interaction_id` | string | 轮次标识，与消息的 `interaction_id` 一一对应 |
| `status` | string | 轮次状态，取值见 §2.4 |
| `state` | string | 状态机取值（主文档 §3.2），用于更细的过程展示 |
| `capability_id` | string \| null | 该轮命中的能力；未命中（闲聊 / 追问 / 失败）时为 `null` |
| `created_at` | string | 轮次开始时间 |
| `completed_at` | string \| null | 轮次结束时间；**非终态时为 `null`**（可据此判断该轮是否还在跑） |
| `error_category` | string \| null | 失败分类码，与 SSE `interaction.failed` 同值（如 `forbidden` / `time_range_missing`）；非失败为 `null` |

### 2.3 ConversationDetail（会话详情 = 整个会话流）

C2 与 C3 **共用同一个响应结构**：

```json
{
  "conversation": { "...": "ConversationSummary（§2.1）" },
  "interactions": [ { "...": "ConversationTurn（§2.2）" } ],
  "messages": [ { "...": "MessageView（§2.6）" } ],
  "next_cursor": null
}
```

- `interactions` 按时间**升序**（最早的在前），且**不分页**（单会话轮次量级很小）。
  **数组顺序就是轮次顺序**：数组第 1 个元素即第 1 轮、第 2 个即第 2 轮……前端可以
  直接用数组下标当"轮次序号"。
- `messages` 按 `(created_at, interaction_id, sequence)` **升序**，即对话的自然时间顺序。
  **数组已排好序，前端拿到后直接按数组顺序渲染，不要自行重排**——尤其不要按
  `sequence` 排（它每轮从 1 重新计数，当全局排序键必然乱序）、不要按 `message_id` 排
  （它是随机生成的标识，不含先后信息）、也不要自己解析 `created_at` 排序。
- `next_cursor` **只表示 `messages` 还有下一页**（`interactions` 永远是一次给全）。
  翻页参数走 C3 自己的 `limit` / `cursor`。游标是服务端签发的**不透明字符串**，
  只做原样回传；游标损坏或来自旧版本时会返回
  `400 {"detail": "pagination cursor is malformed"}`，从头重新拉取即可。
- **稳定形状**：C2 / C3 的响应会**显式返回 `null`**（如 `"title": null`、
  `"completed_at": null`），不会省略键。可以放心按固定 TS 接口类型消费。
  （例外：`MessageView.payload` 在无卡片时为 `null`；`messages[].created_at` 恒有值。）

### 2.4 `status` 与 `kind` 取值

`status`（轮次状态，与主文档 §3.2 同源）：

| 值 | 含义 | 前端建议 |
| --- | --- | --- |
| `pending` | 已受理未开始 | 加载态 |
| `running` | 处理中 | 加载态 |
| `completed` | 正常收尾（含追问收尾，见 `state`） | 终态 |
| `failed` | 失败 | 终态，按 `error_category` / `error` 消息文案展示 |
| `cancelled` | 用户取消 | 终态，标「已取消」 |

`kind`（消息类型）：

| `kind` | 含义 | 会话流中是否返回 |
| --- | --- | --- |
| `plain_text` | 用户提问 | ✅ |
| `chat` | 闲聊应答 | ✅ |
| `clarification` | 追问 | ✅ |
| `result_table` | 结果（含卡片 `payload`） | ✅ |
| `error` | 失败 / 取消的友好文案 | ✅ |
| `thinking` | 该轮推理原文（刷新后恢复折叠块用） | ✅ |
| `phase` | 过程行（鉴权 / 取数 / 计算） | ✅ 默认返回，需要时可让服务端剔除（§4 `exclude_kinds`） |

> `phase` **默认返回**，与既有 `GET /v1/sessions/{session_id}/messages` 行为一致，
> 避免两套读取路径渲染差异。现有前端在恢复会话时已自行过滤 `kind !== 'phase'`，
> 可继续沿用；若希望减小响应体积，用 C3 的 `exclude_kinds=phase`。

### 2.5 标题（`title`）派生规则

服务端**确定性派生，不调用模型**（标题属非必要元数据，避免业务字段进提示词）：

1. 取该会话**最早的** `role="user"`、`kind="plain_text"` 消息的 `text`；
2. 折叠首尾空白、换行与连续空格；
3. 截断到 **30 个字符**（按 Unicode 码点计，不会切坏汉字），超出补 `…`；
4. 没有可用消息 → `title = null`。

**标题不可编辑**（无 `PATCH` 接口）；服务端也**不做** AI 摘要标题。

### 2.6 MessageView（消息，比主文档 §3.3 多两个字段）

```json
{
  "message_id": "msg_xxx",
  "interaction_id": "it_7d3a1c20",
  "role": "assistant",
  "kind": "result_table",
  "sequence": 6,
  "text": "已返回 1 行结果。",
  "created_at": "2026-09-21T02:15:33+00:00",
  "payload": {
    "capability_id": "fr002_own_wage",
    "columns": ["rq", "gongzi"],
    "row_count": 1,
    "artifact_id": "art_xxx",
    "card": { "...": "结果卡片，见主文档 §5.3.1" }
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `interaction_id` | **消息所属轮次**。这是把消息归回「轮」的关键：没有它只能线性拼接消息，也拿不到每轮的收尾状态 |
| `created_at` | 消息创建时间（按轮展示时间戳用） |
| `payload` | 仅 `kind="result_table"` 时非 `null`，承载结果卡片元数据，**刷新后重建卡片与实时渲染完全一致**（含 `card` 与 `time_range`，因此刷新后点卡片下钻仍能拿到原窗口） |
| `sequence` | 该消息在**轮内**的单调递增序号，与 SSE 的 `id:` 同源。**每轮都从 1 重新计数**，因此它只能用于同一轮内比较先后，**绝对不能**当整个会话的排序键（否则第 2 轮起全部错位）。整条 `messages` 数组的顺序服务端已保证正确，直接按数组顺序渲染即可 |

### 2.7 老接口的向后兼容

`GET /v1/sessions/{session_id}/messages`（主文档 §4.5）**继续可用，行为不变**，
只是消息里**新增**了 `interaction_id` / `created_at` 两个字段（加法式变更，旧前端可忽略）。
新前端**推荐统一改用 C3**——C3 是它的超集（多了会话元信息与 `interactions`）。

## 3. C1 获取历史会话列表

```http
GET /v1/conversations?limit=20&cursor=<opaque>
```

请求头：`X-Factory-Credential`（必带）。

| Query | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `limit` | 否 | `20` | 范围 1–100，**超出范围由服务端夹紧**（传 0→1，传 999→100），不会报错 |
| `cursor` | 否 | — | 上一页返回的 `next_cursor`，原样回传 |

排序：`updated_at DESC, session_id DESC`（最近有活动的排最前，与前端「活跃会话置顶」的预期一致）。

响应 `200`：

```json
{
  "items": [
    {
      "session_id": "sess_2f1c9b748a3e4d6f9c216c1f0a7b5e10",
      "title": "我这个月的工资是多少",
      "created_at": "2026-09-21T02:15:31+00:00",
      "updated_at": "2026-09-21T02:18:04+00:00",
      "message_count": 7,
      "interaction_count": 2,
      "last_message": {
        "role": "assistant",
        "kind": "result_table",
        "text": "已返回 1 行结果。",
        "created_at": "2026-09-21T02:18:04+00:00"
      },
      "last_status": "completed"
    },
    {
      "session_id": "sess_a91b0c331d4e4a778b029f8e7d6c5b4a",
      "title": null,
      "created_at": "2026-09-20T07:41:12+00:00",
      "updated_at": "2026-09-20T07:41:12+00:00",
      "message_count": 0,
      "interaction_count": 0,
      "last_message": null,
      "last_status": null
    }
  ],
  "next_cursor": null
}
```

要点：

- `items: []` 是合法的「这个人还没有历史会话」，**不是错误**（没有任何历史时返回
  `200 {"items": [], "next_cursor": null}`，不会 404）。请直接展示空态，不要报错。
- 新建但**从未提问**的会话（`interaction_count = 0`、`title = null`）**也会出现在列表里**。
- **列表不返回消息正文**（只有一行预览），避免一次拉回全部历史；正文按需走 C3。
- 该用户**所有**会话都在列表内，**不按角色过滤**（角色由凭据决定且相对稳定，
  会话归属只看「租户 + 用户」）。

## 4. C2 新建会话

```http
POST /v1/conversations
Content-Type: application/json
```

请求体**可选**：

```json
{ "session_id": "2f1c9b74-8a3e-4d6f-9c21-6c1f0a7b5e10" }
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `session_id` | 否 | 前端自己生成的会话标识（便于与现有「前端生成 UUID」实现平滑对接）。约束：**1–128 字符，仅 `A-Za-z0-9_-`**（不含 `/`、空格、中文）。**不传则由服务端生成**（形如 `sess_<32 位 hex>`）并返回 |

也可以完全不传请求体（`POST /v1/conversations` 空 body），服务端生成 `session_id`。

### 4.1 首次创建 → `201`

```json
{
  "conversation": {
    "session_id": "sess_2f1c9b748a3e4d6f9c216c1f0a7b5e10",
    "title": null,
    "created_at": "2026-09-21T13:22:10+00:00",
    "updated_at": "2026-09-21T13:22:10+00:00",
    "message_count": 0,
    "interaction_count": 0,
    "last_message": null,
    "last_status": null
  },
  "interactions": [],
  "messages": [],
  "next_cursor": null
}
```

### 4.2 重复调用（幂等）→ `200`

**幂等是硬约定**：同一 `(租户, 用户)` 下 `session_id` 已存在时，返回 **`200`**（不是 `201`），
body 是**该会话当前的完整详情**（结构与 §4.1 相同，但 `conversation` /
`interactions` / `messages` 都是真实内容）。

因此：

- 前端「新对话」按钮**连点**、或网络重试，都不会产生第二个会话，也**不会清空**已有消息；
- **「新建即展示整个会话流」**：拿到响应后**不需要**再调 C3，直接用
  `conversation` + `interactions` + `messages` 渲染即可（新会话是空流；重放已存在的
  `session_id` 会直接看到历史）。
- 前端可以**只用状态码**区分「新建成」还是「复用了已有的」：`201` = 新建，`200` = 已存在。

### 4.3 约束与错误

| 状态 | 场景 | `detail` |
| --- | --- | --- |
| `201` | 新建成功 | — |
| `200` | `session_id` 已存在（幂等复用） | — |
| `400` | **单用户会话数达到上限 500**，不新建 | `conversation limit reached` |
| `422` | `session_id` 格式非法（超长 / 含非法字符） | FastAPI 标准校验结构 |
| `403` | 身份/租户被拒绝（含 `tenant_disabled`） | 见主文档 §6.1 |
| `503` | 会话存储未配置（部署问题） | `session store is not configured` |

- **单用户会话数上限 500**（含空会话）。达到上限时**不新建**并返回 `400`；
  前端提示「会话数量已达上限，请使用已有会话继续提问」。
  本期没有删除接口，所以不要把提示写成「请删除旧会话」。
- 上限**只在 C2 建档时校验**，**不影响**既有会话继续提问（提问走主文档 §4.2，接口不变）。
- 请求体除 `session_id` 外不接受任何字段；含身份 / 租户 / 范围字段会被忽略。
- 该接口**不调用客户 MES、不调用模型、不产生用量计量**。

## 5. C3 会话详情（整个会话流）

```http
GET /v1/conversations/{session_id}?limit=50&cursor=<opaque>&exclude_kinds=phase
```

| Query | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `limit` | 否 | `50` | 消息分页大小，上限 **200**，超出由服务端夹紧 |
| `cursor` | 否 | — | 消息翻页游标，取上一页的 `next_cursor` |
| `exclude_kinds` | 否 | — | 逗号分隔的**排除**列表（如 `phase` 或 `phase,thinking`），**只做减法** |

响应 `200`：`ConversationDetail`（§2.3）。

要点：

- **一次请求给出整个会话流的骨架**：`conversation`（元信息）+ `interactions`（全部轮次）
  + `messages`（第一页消息）。消息超过 `limit` 时继续用 `next_cursor` 翻页。
- `exclude_kinds` **只影响 `messages`**；`conversation.message_count` 仍按固定口径
  （已排除 `phase`）返回，不会因过滤参数而漂移。
- `exclude_kinds` 里出现**未知取值 → `400`**（`detail` 形如 `unknown message kind: foo`）。
  这是刻意的：拼错会导致「本该被隐藏的行反而返回」，所以直接报错而不是静默忽略。
- 会话不存在**或不属于当前身份** → `404 {"detail": "conversation not found"}`（两者不可区分）。
- 幂等、零副作用，可安全重试与并发调用。

推荐渲染方式：

1. **以 `interactions[]` 数组为轮次框架**（数组顺序即轮次顺序，下标即轮次序号），
   把 `messages` 按 `interaction_id` 分组挂到各自的轮上；每组以
   `kind="plain_text"` 的用户气泡开头；
2. 组内消息**保持服务端返回顺序**（等价于轮内 `sequence` 升序），不要重排；
3. 用同一 `interaction_id` 在 `interactions[]` 里找到该轮的 `status` / `error_category`，
   决定这一组怎么收尾（失败文案、取消标记、导出入口）；
4. `completed_at === null` 说明该轮还在进行中，可展示加载态。

## 6. 错误码汇总

| 状态 | 在会话接口中的场景 | `detail` 示例 |
| --- | --- | --- |
| `400` | C2 会话数达上限；C3 `exclude_kinds` 取值非法；**翻页游标损坏或来自旧版本** | `conversation limit reached` / `unknown message kind: foo` / `pagination cursor is malformed` |
| `401` | 凭据缺失、被拒绝或非法 | `credential header is missing` / `credential was rejected` |
| `403` | 身份解析被拒（租户/用户不存在或不可用）；**租户被平台停用** | `unauthenticated` / `forbidden` / `tenant_disabled` |
| `404` | C3 会话不存在**或属于其他身份**（刻意不可区分） | `conversation not found` |
| `422` | C2 请求体 `session_id` 格式非法 | FastAPI 标准校验结构 |
| `502` | token 网关不可用，凭据换取失败 | `token exchange is unavailable` |
| `503` | 会话存储未配置 | `session store is not configured` |

> `400` / `404` 都不会返回「存在但无权」的信息；`404` 一律按「不存在」处理。

```ts
// frontend/src/services/api.ts 新增
import type {
  ConversationDetail,
  ConversationPage,
} from '@/types/assistant'

/** C1 当前身份的历史会话列表（按 updated_at 倒序） */
export function listConversations(cursor?: string, limit = 20) {
  const q = new URLSearchParams({ limit: String(limit) })
  if (cursor) q.set('cursor', cursor)
  return request<ConversationPage>(`/v1/conversations?${q}`)
}

/**
 * C2 新建会话；幂等。
 * - 201：新建成功
 * - 200：session_id 已存在，body 是该会话当前的完整详情
 * 两种状态都返回可直接渲染的 ConversationDetail，无需再调 getConversation。
 */
export async function createConversation(sessionId?: string): Promise<{
  created: boolean
  detail: ConversationDetail
}> {
  const res = await requestRaw<ConversationDetail>('/v1/conversations', {
    method: 'POST',
    body: JSON.stringify(sessionId ? { session_id: sessionId } : {}),
  })
  return { created: res.status === 201, detail: res.data }
}

/** C3 会话详情（整个会话流）；excludeKinds 传 ['phase'] 可省掉过程行 */
export function getConversation(
  sessionId: string,
  opts: { cursor?: string; limit?: number; excludeKinds?: string[] } = {},
) {
  const q = new URLSearchParams()
  q.set('limit', String(opts.limit ?? 50))
  if (opts.cursor) q.set('cursor', opts.cursor)
  if (opts.excludeKinds?.length) q.set('exclude_kinds', opts.excludeKinds.join(','))
  return request<ConversationDetail>(
    `/v1/conversations/${encodeURIComponent(sessionId)}?${q}`,
  )
}
```

> 上面 `createConversation` 需要能读到状态码。若现有 `request()` 封装只返回 body，
> 用项目里等价的「返回 `{status, data}`」方法替换 `requestRaw` 即可。

现有前端 `Conversation` 类型（`id` / `title` / `role` / `messages` / `updatedAt`）的映射：

```ts
function toLocalConversation(s: ConversationSummary) {
  return {
    id: s.session_id,
    // title 为 null 时兜底，避免列表出现空白项
    title: s.title ?? '新对话',

    // 列表预览：thinking 不展示推理原文，用占位文案

      : (s.last_message?.text ?? ''),
    lastStatus: s.last_status,
    messageCount: s.message_count,
    interactionCount: s.interaction_count,
    // 正文不在列表里，需要时用 getConversation(s.session_id) 拉取
    messages: [] as MessageView[],
  }
}
```

## 8. 推荐接入流程

目标：**替换现有「`localStorage` 只存最后一个会话」的实现**，改为服务端驱动。

1. **打开历史面板** → `listConversations()` → 按返回顺序渲染（服务端已按
   `updated_at` 倒序，前端**不要**再排一次）。`title` 为 `null` 显示「新对话」。
2. **点「新对话」** → `createConversation()` → 用返回的 `conversation.session_id` 作为当前会话，
   并**立即**把该会话插入/置顶本地列表（无需重新拉 C1）。
   后续提问仍走主文档 §4.2 `POST /v1/sessions/{session_id}/interactions`，**该接口不变**。
3. **点历史会话** → `getConversation(session_id)` → 按 `messages[].interaction_id`
   归组到 `interactions[]`，渲染整个会话流（§5 的渲染建议）。
   卡片下钻与导出沿用主文档 §4.2 / §4.10。
4. **一轮问答结束后**：收到终态事件时可选择
   （a）重新 `listConversations()` 让排序与预览同步，或
   （b）本地就地更新该会话的 `last_message` / `updated_at` / `last_status` 并重新置顶，
   省掉一次请求。两种都可以；建议先用 (a) 保证正确性，后续再优化成 (b)。
5. **刷新页面恢复**：不再依赖 `localStorage` 里的 `session_id`。
   默认恢复「列表里第一个会话」或「上次打开的那个 `session_id`（可选继续存本地做 UI 记忆）」；
   即使本地什么都没存，也能从 C1 完整恢复历史。

可以分批上线：

| 批次 | 内容 | 是否依赖后端 |
| --- | --- | --- |
| 第一批 | 按 §7 定义类型与调用函数；「刷新恢复」从 `localStorage` 单会话切到 C1 列表 + C3 详情 | 否（接口已可用） |
| 第二批 | 「新对话」改调 C2 拿 `session_id`，新会话立即进列表 | 否（接口已可用） |
| 第三批（可选） | 会话归档、标题编辑 | 本期无接口，暂不做 |

## 9. 本期明确不做：会话删除

**本期不提供 `DELETE /v1/conversations/{session_id}`**，前端历史面板**不放删除入口**。
只需「列表 + 新建 + 详情」即可闭环。

不做的原因是产品与合规口径，而非实现难度：

1. **不可恢复**：硬删是物理删除，误触即永久丢失对话，与「保留期内可回看」的习惯冲突。
2. **保留期与审计边界**：会话正文是否需要与用量计量保持同一留存口径，需产品一并明确。
3. **产品预期未定**：用户能否自主删除自己的对话、删除是软删（归档）还是硬删，需产品确认。

将来的落地方向优先取**软删**（在会话表加 `archived_at`），并让 C1 / C3 统一过滤已归档会话。

## 10. 联调自查清单

- [ ] 空历史（全新用户）→ C1 返回 `200 {"items": [], "next_cursor": null}`，前端展示空态而非报错。
- [ ] C2 全新 `session_id` → `201`；同一 `session_id` 再调一次 → `200` 且 `messages` 不被清空。
- [ ] C2 不传 `session_id` → 服务端生成并在响应里返回，之后能用它提问、出现在 C1 里。
- [ ] C2 传非法 `session_id`（含 `/`、中文、超 128 字符）→ `422`。
- [ ] C1 翻页：`limit=2` 连续翻到底，不重不漏，最后一页 `next_cursor === null`。
- [ ] C3 `messages` 升序、`interactions` 升序；`messages[].interaction_id` 都能在
      `interactions[]` 里找到对应轮次。
- [ ] C3 排序口径自查：渲染**直接使用 `messages` 数组顺序**，代码里没有按
      `sequence` / `message_id` / 自行解析 `created_at` 重排的逻辑
      （`sequence` 每轮从 1 重新计数，当全局排序键会把第 2 轮起的消息全部排错）。
- [ ] 同一轮内多条智能体消息（思考过程 → 结果卡片 → 最终回答）刷新后顺序与实时一致。
- [ ] C3 用别人的 `session_id` → `404 conversation not found`（与「不存在」表现一致）。
- [ ] C3 `exclude_kinds=phase` → 响应中没有 `phase` 消息，且 `message_count` 不变。
- [ ] C3 `exclude_kinds=foo` → `400 unknown message kind: foo`。
- [ ] 刷新页面后，结果卡片（`payload` / `payload.card` / `payload.time_range`）
      与实时渲染一致，**点卡片下钻仍能用原时间窗口**。
