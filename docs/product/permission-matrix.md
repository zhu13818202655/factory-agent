# 权限矩阵

## 能力矩阵

| 能力 | 员工 | 管理 | 老板 |
|---|---:|---:|---:|
| FR-001 个人产量 | 本人 | 可查询本人；下属能力另行定义 | 仅通过 FR-012 查询员工 |
| FR-002/003 个人工资 | 本人 | 本人 | 仅通过 FR-012 查询员工 |
| FR-004 组内收入排名 | 本人所在组中的本人名次 | 否 | 否 |
| FR-005/006 订单进度与产量 | 否 | 管辖组织 | 全厂能力使用 FR-009 |
| FR-007 小组/车间对比 | 否 | 管辖组织 | 可按全厂范围查询 |
| FR-008 员工工资清单 | 否 | 管辖员工 | 全厂能力使用 FR-011/012 |
| FR-009~012 老板能力 | 否 | 否 | 活动租户全厂 |

该表是产品基线，不代表客户现有角色编码。`DEC-002` 关闭后，角色映射才能进入 ready
Story。任何扩大数据范围的修改都需要人工批准并更新安全测试。

## 强制顺序

1. 从可信身份边界解析用户及其授权租户成员关系；可信凭据携带 `(tenant_id, user_id)` 二元组，
   唯一定位一条成员关系（一人一租户，`DEC-011` 已关闭）。
2. 为本次 MES 业务交互建立可信活动 `TenantContext`；换租户等于换一组可信凭据重新鉴权，
   不存在会话内切换入口。
3. 获取活动租户内的角色、组织关系与管辖范围，生成不可变 `DataScope`。
4. 检查角色是否允许使用目标能力。
5. 将用户筛选条件与 `DataScope` 求交集。
6. 仅把活动租户和求交后的 ID 参数传给 MES Adapter。
7. 对拒绝场景断言业务 API 调用次数为零。

活动 `tenant_id` 必须来自可信凭据二元组唯一解析的授权成员关系。用户文本、普通业务参数和
LLM 输出都不能声明租户成员关系，也不能扩大 `tenant_id`、`dept_ids`、`employee_ids`。平台
运营请求使用独立 `PlatformScope`，工厂员工、管理和老板角色都不能获得跨租户运营权限。

## 待确认

- `DEC-001`：一人多组和组织调动期间的数据范围。
- `DEC-002`：身份、角色和管辖范围的可信来源。
- `DEC-011`（已关闭）：业务确认一人一租户。凭据二元组 `(tenant_id, user_id)` 唯一定位成员
  关系，A1 返回单对象；命中多条按数据错误拒绝。每条成员关系恰好一个角色
  （`employee|manager|owner`），manager 的范围定义天然包含本人数据，不使用多角色并集。
- `DEC-012`：订单/款号归属活动租户的可信预检来源。当前 Canonical 无订单授权解析接口，安全
  默认是无法证明归属即拒绝。
- `DEC-013`：平台运营身份的来源与凭据边界，不得复用工厂员工、管理、老板角色。
- `DEC-014`：审计写入失败时拒绝请求还是降级放行。当前暂定拒绝。
- 管理者是否可查询自己不直接管理但属于上级车间的组织。
- 老板角色是否存在全厂之外的区域/法人范围。
