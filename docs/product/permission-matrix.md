## 权限责任归属

**行级数据权限由 MES 完成（M3）**。MES 按调用者身份的 company、dept 和 `move_admin_role`
自动过滤返回数据；`move_admin_role="00"` 的角色只能查看本人数据（M19）。我方不获取、不判断
用户角色（M11），也不拼接任何数据范围过滤条件。

MES **没有专门的权限错误码**：权限不足通常表现为按配置过滤后无数据（M12）。因此我方按
「返回范围明显小于请求范围 = 可能无对应权限」判断并给出友好提示，不把收窄结果呈现为完整结果。

## 能力矩阵

下表是**产品语义基线**，描述各角色预期能看到什么，用于产品验收与话术设计。它不是运行时判定
依据——运行时可见范围完全由 MES 决定。客户角色枚举尚未提供（第五章 A.1），角色不进入
`authorize()` 判定。

| 能力 | 员工 | 管理 | 老板 |
|---|---|---|---|
| FR-001 个人产量 | 本人 | 本人 | 本人；查他人用 FR-012 |
| FR-002/003 个人工资 | 本人 | 本人 | 本人；查他人用 FR-012 |
| FR-005/006 订单进度与产量 | 否 | MES 过滤后范围 | MES 过滤后范围 |
| FR-007 车间产量对比 | 否 | MES 过滤后范围 | MES 过滤后范围 |
| FR-008 员工工资清单与排名 | 否 | MES 过滤后范围 | MES 过滤后范围 |
| FR-009~011 全厂总览类 | 否 | MES 过滤后范围 | MES 过滤后范围 |
| FR-012 任一员工工资 | 否 | 否 | 目标员工须在本租户内可解析 |

FR-004 组内收入排名已取消（M7：员工端接口只返回本人数据）。

## `DataScope` 语义

`DataScope` 是不可变值，只提供收窄方法：

| 字段 | 来源 | 说明 |
|---|---|---|
| `tenant_id` | 明文 app_key（M4） | 一厂一 Key，天然唯一；不存在活动租户切换 |
| `employee_ids` | token 响应的 `user`（M10） | 当前只含本人工号 |
| `dept_ids` | `EmployeeQuery` / `DeptQuery` 的当前归属 | 单层车间（M5），只取最新关系（K2） |
| `mes_filtered` | Adapter 边界设置 | 表示更大范围由 MES 过滤，我方不声明该范围 |
| `evaluated_at` / `scope_version` | 注入时钟 | 参与缓存 key 与失效 |

`mes_filtered` 不提供任何扩大 API，且不可由用户输入或模型输出设置。

## 强制顺序

1. 从可信 header 取得客户凭证包（accessToken、明文 app_key、sign、timestamp、`user`、`uname`）。
   凭证包不接受来自请求体、查询参数、自然语言或模型输出。
2. 绑定 `tenant_id` = 明文 app_key，`employee_id` = `user`。
3. 从 `EmployeeQuery`/`DeptQuery` 取当前车间归属，生成不可变 `DataScope`。
4. 检查目标能力是否已注册且已启用。
5. 将用户筛选条件与 `DataScope` 求交；空交集判定为拒绝。
6. 仅把求交后的参数与凭证公共参数传给 MES Adapter。
7. 对返回结果做 M12 范围收窄判定，必要时给出友好提示。
8. 对拒绝场景断言业务 API 调用次数为零。

用户文本、普通业务参数和 LLM 输出都不能改变 `tenant_id`、`employee_ids`、`dept_ids` 或
`mes_filtered`。平台运营请求使用独立 `PlatformScope`，工厂身份无法获得跨租户运营权限。
