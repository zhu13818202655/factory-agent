# 权限矩阵

## 能力矩阵

| 能力 | 员工 | 管理 | 老板 |
|---|---:|---:|---:|
| FR-001 个人产量 | 本人 | 可查询本人；下属能力另行定义 | 仅通过 FR-012 查询员工 |
| FR-002/003 个人工资 | 本人 | 本人 | 仅通过 FR-012 查询员工 |
| FR-004 组内收入排名 | 本人所在组中的本人名次 | 否 | 否 |
| FR-005/006 订单进度与产量 | 否 | 管辖组织 | 全厂能力使用 FR-009 |
| FR-007 小组/车间对比 | 否 | 管辖组织 | 可按全厂范围查询 |
| FR-008 员工工资清单 | 否 | 管辖员工 | 全厂能力使用 FR-011/012 |
| FR-009~012 老板能力 | 否 | 否 | 活动租户全厂 |

该表是产品基线，不代表客户现有角色编码。`DEC-002` 关闭后，角色映射才能进入 ready
Story。任何扩大数据范围的修改都需要人工批准并更新安全测试。

## 强制顺序

1. 从可信身份边界解析用户及其授权租户成员关系。
2. 为本次 MES 业务交互解析一个可信活动 `TenantContext`；切换租户必须重新鉴权。
3. 获取活动租户内的角色、组织关系与管辖范围，生成不可变 `DataScope`。
4. 检查角色是否允许使用目标能力。
5. 将用户筛选条件与 `DataScope` 求交集。
6. 仅把活动租户和求交后的 ID 参数传给 MES Adapter。
7. 对拒绝场景断言业务 API 调用次数为零。

活动 `tenant_id` 必须属于可信身份的授权租户集合。用户文本、普通业务参数和 LLM 输出都不能
声明租户成员关系，也不能扩大 `tenant_id`、`dept_ids`、`employee_ids`。平台运营请求使用独立
`PlatformScope`，工厂员工、管理和老板角色都不能获得跨租户运营权限。

## 待确认

- `DEC-001`：一人多组和组织调动期间的数据范围。
- `DEC-002`：身份、角色和管辖范围的可信来源。
- 管理者是否可查询自己不直接管理但属于上级车间的组织。
- 老板角色是否存在全厂之外的区域/法人范围。
