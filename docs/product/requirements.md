# 产品需求基线

> 更新日期：2026-08-20
> 实施顺序：`.github/story/#1.md` 至 `.github/story/#9.md`

## 产品目标

`factory-agent` 是只读、API-only 的工厂 MES 智能体后端。它让员工、管理者和老板通过
自然语言查询权限范围内的产量、工资、订单进度和排名，并获得可审计的结构化结果与
Excel 报表。

所有业务取数必须先完成身份与 `DataScope` 校验，结果必须来自已验证的 MES API 数据。

## 角色与数据范围

| 角色 | 数据范围 | 主要能力 |
|---|---|---|
| 员工 | 仅本人；排名限本人所属小组 | 个人产量、个人工资、工资明细、组内收入排名 |
| 管理 | 本人及明确管辖的车间、小组和员工 | 订单/款号进度与产量、产量对比、员工工资清单 |
| 老板 | 当前租户全厂 | 全部订单、车间产量、全厂工资、任一员工工资 |

“全厂”始终受 `tenant_id` 限制，不代表跨租户访问。一人多组和管理者管辖闭包仍需
`DEC-001`、`DEC-002` 确认。

| ID | 角色 | 能力 | 最小输出 | 待决事项 |
|---|---|---|---|---|
| FR-001 | 员工 | 个人产量统计 | 日期、款号、工序、完成、合格、次品 | DEC-004 |
| FR-002 | 员工 | 个人工资日/月汇总 | 区间、工资合计、计件件数、日均 | DEC-003、DEC-005 |
| FR-003 | 员工 | 个人工资明细 | 日期、款号、工序、单价、数量、小计 | DEC-003、DEC-005 |
| FR-004 | 员工 | 组内收入排名 | 本人排名、金额、组内人数 | DEC-001、DEC-003 |
| FR-005 | 管理 | 订单/款号进度 | 当前/已完成工序、在制、完工、进度 | DEC-006、DEC-007、DEC-010 |
| FR-006 | 管理 | 订单/款号产量 | 各工序产量、合计、参与人数 | DEC-010 |
| FR-007 | 管理 | 小组/车间产量对比 | 总量、人均、达成率、名次 | DEC-008 |
| FR-008 | 管理 | 员工工资清单 | 员工、小组、计件数、工资合计 | DEC-003、DEC-005 |
| FR-009 | 老板 | 全厂订单进度总览 | 订单、客户、下单量、完工、进度、预警 | DEC-006、DEC-009 |

每项能力必须支持明确时间范围、权限负向测试、固定数据 golden 结果和 Excel 导出。字段可在
客户契约明确后增补，但不能未经决策改变金额、进度、达成率或权限语义。

## 公共产品能力

- FR-013：每类结果生成结构化卡片和 Excel，文件名为
  `角色_功能_时间范围_生成时间`，下载必须再次鉴权。
- FR-014：识别意图以及时间、订单、款号、组织和人员参数。
- FR-015：缺少必要参数时追问，并支持“换成上个月”“看二车间”等上下文补丁。
- FR-016：越权时不调用业务 API，返回友好提示及当前角色可用能力。
- FR-017（P1）：角色快捷问题、历史、收藏和一键复问。
- FR-018（P1）：每日早报和工资结果通知，渠道与触发规则待确认。

## 非功能要求

- 多租户隔离叠加员工/管理/老板三级行级权限。
- 工资明细等敏感原始数据不得进入 LLM prompt、日志、trace、错误或快照。
- 所有查询和导出记录审计，至少保留 180 天。
- MES 调用只读、幂等、有界；不能由模型构造 URL、鉴权或任意查询。
- 可用性目标为 99.9%，具体 SLI、依赖降级和性能阈值在生产准入 Story 固化。

## API-only 边界

原需求包含 PC/App 悬浮助手、拖拽浮标、移动布局、语音输入和大字模式。它们属于 MES
前端或 App，不在本仓库实现。本服务负责提供会话/SSE、角色化能力、结果卡片数据、导出下载、
历史收藏和通知所需的后端接口。前端联调契约在对应 Story 中定义。

## 明确非目标

- 写入或修改客户 MES 数据。
- 在后端实现语音识别、PC/App UI 或大字模式。
- 首期图表、PDF、DOCX 报表。
- 用 L2 开放规划替代首期 12 项确定性 L1 能力。
- 在客户规则未确认时自行定义工资、进度、达成率或预警公式。
