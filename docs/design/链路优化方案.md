> 两条**实测推翻计划假设**的发现（已回填 T2.1/T2.3 与 §3.5）：
> 1. **S3 根路径不能当就绪判据**。种子化凭据后，未签名的 `GET /` 被网关拒成 **403**，

>    `/cluster/status`（200，无需凭据），实测 9 秒内转 healthy。

>    因此「桶名写错」在 SeaweedFS 上**不会**触发 fail-closed，只会把产物写进另一个桶。
>    计划里「桶不存在时上传报错」的完成标准不成立（见 T2.3）。

  `--combos 120 --latency-ms 300 --repeat 3`（串行墙钟上界 = 120 × 300ms = 36000ms）：

  | 并发 | p50 耗时 | 相对串行 | fan-out 请求数 | 峰值并发 | 结果一致 |
  |---|---|---|---|---|---|
  | 1 | 36242 ms | 1.00x | 120 | 1 | 一致 |
  | 2 | 18185 ms | 1.99x | 120 | 2 | 一致 |
  | 4 | 9142 ms | 3.96x | 120 | 4 | 一致 |
  | 8 | 4629 ms | 7.83x | 120 | 8 | 一致 |

  **结论**：加速比与并发度近似线性，峰值并发严格等于开关值（无超发），结果指纹与串行
  完全相同（`incomplete=False`、`reason=None`）。**未证实的部分**：真实网关的 429/超时行为
  只能在对客户 MES 的联调环境实测；在上生产前须按 T5.11 的通过线补测。

## 3. 关键设计细节

### 3.1 任务 A：为什么是「合并 + 独立兜底」而不是二选一

现状调用点：本地权限矩阵通过之后、业务过滤解析之前（`session/pipeline.py:282-298` → `session/consistency.py:39-124`）；失败即 fail-open，且**不记 usage 事件**（`session/consistency.py:67-96`）。

合并后：正常路径省一次往返；但 EXTRACT 的 JSON 一旦非法就会同时丢掉能力与护栏（走 REPAIR 一次，仍非法则整体 `model_output_invalid`），比今天「护栏失败仅 fail-open」更硬 → 因此保留独立调用作为二级兜底，把可用性耦合降回可接受水平。

### 3.2 任务 B：为什么红线不过要回落而不是拒答

`_build_slots` 现状已是「LLM ISO 优先、缺失才走规则」（`intent.py:345-357`），今天的 366 天判定在下游 pipeline，超限直接友好拒答（`session/pipeline.py:373-383`）。若把红线校验放在主路径之前却不做回落，模型把「本月」解析成 2 年区间时会从「返回一个月明细」变成「时间范围超出上限」——纯回归。因此红线顺序是：

```
LLM ISO 合法 且 通过红线 → 采用
否则（缺失 / 非法 / 越限）→ 规则层兜底
两者都失败 → ambiguous → 追问（现状路径）
```

### 3.3 任务 D：为什么只动这两处提交

相邻的 `AUTHORIZING` → `EXECUTING` 之间没有任何工作，合并是零风险收益；而 `scope_resolution_started` 对无名称槽位的查询纯属噪声。其余提交点承担「实时/重放/历史三路一致」的可见性语义，本次不动。

### 3.4 任务 E：三段耗时的定义

| 字段 | 定义 | 来源 |
|---|---|---|
| `duration_ms` | 交互总墙钟（`updated_at − created_at`，含排队） | `session/base.py:159`（不变） |
| `llm_duration_ms` | 本交互全部 LLM 事件 `duration_ms` 之和（含失败尝试） | 新增，来自 `usage_events` |
| `mes_duration_ms` | kernel 实测执行总时长 | `result.duration_ms`（**语义不变**） |
| `local_duration_ms` | `max(0, 总 − llm − mes)`，**残差**：含排队等待与本地计算 | 新增 |

### 3.5 S3 后端与下载路径

- **后端代理下载不变**：owner 复核 + 审计事件成功后才放数据，审计失败 503（`api/exports.py:105-137`，DEC-014）。presigned URL 会把「审计失败即不放数据」降级为「URL 即令牌」，本次不引入。
- **对象布局**：`exports/{artifact_id}.xlsx` + `exports/{artifact_id}.json`（sidecar 保存 owner/filename/content_type/expires_at）。用 sidecar 而非 S3 头字段，避免中文文件名在头字段里的编码问题，且与今日本地布局 1:1 对应。
- **错误映射**：连接失败 / 凭据错误 / 写入失败 → `ExportError(UNAVAILABLE)`（与今日「落盘不可写即 fail-closed」一致）；读取失败或元数据缺失 → `None` → 404（与「缺失/过期/他人」不可区分一致）。
  - **实测修正（T2.3）**：**不要**把「桶不存在」列为 fail-closed 触发条件——SeaweedFS 对不存在的桶
    会自动建桶，PUT 静默成功、对象可读回。因此桶名写错的后果是「产物落在另一个桶」，而不是报错。
    真正会触发的只有：网关不可达、凭据错误、客户端异常。若要防桶名写错，只能加一层显式的
    启动/就绪期 `HeadBucket` 校验（**本次未做，列为可选项**）。
- **凭据与端点**：容器内用服务名 `http://seaweedfs:8333`，宿主机调试用 `http://127.0.0.1:8333`，均由 env 决定；路径风格寻址开启（`addressing_style=path`），避免依赖 DNS 的虚拟主机风格。
- **SeaweedFS 形态**：单节点 `weed mini`（官方定位适用于单节点生产，含 S3 网关）；不引入多 master / 多 volume 集群，也不引入 Erasure Coding（开源版固定比例，且本次数据量与保留窗口都不需要）。

## 4. 验收

### 4.1 取数 SQL（原文档 2.5 的方式）

```sql
-- 分阶段耗时分布（灰度前/后各取一段窗口对比）
SELECT event_type,
       percentile_disc(0.5)  WITHIN GROUP (ORDER BY (payload->>'duration_ms')::int) AS p50,
       percentile_disc(0.95) WITHIN GROUP (ORDER BY (payload->>'duration_ms')::int) AS p95
FROM usage_event
WHERE event_type IN ('interaction_completed','llm_call_completed','mes_call_completed')
  AND occurred_at >= :window_start
GROUP BY event_type;

-- 三段耗时与恒等式
SELECT occurred_at,
       payload->>'duration_ms'       AS total,
       payload->>'llm_duration_ms'   AS llm,
       payload->>'mes_duration_ms'   AS mes,
       payload->>'local_duration_ms' AS local
FROM usage_event
WHERE event_type = 'interaction_completed' AND occurred_at >= :window_start
ORDER BY occurred_at DESC LIMIT 50;

-- 单次交互 LLM 调用次数（护栏合并后应从 3 → 2）
SELECT payload->>'interaction_id' AS interaction_id, count(*) AS llm_calls
FROM usage_event
WHERE event_type = 'llm_call_completed' AND occurred_at >= :window_start
GROUP BY 1 ORDER BY 2 DESC;
```

## 5. 风险与不变式核对

| 不变式 / 风险 | 结论 |
|---|---|
| 授权先于任何业务数据调用 | 成立：护栏无论如何都在 `_runner.run` 之前 |
| 越权只收紧不放宽 | 成立：verdict 语义、值域、失败方向均不变；拒绝文案仍由本地生成 |
| 敏感字段不进 prompt/日志/快照 | 成立：S3 sidecar 只存 owner 标识与文件名，不存业务行；下载审计仍只记 artifact id + scope 摘要 |
| 实时/重放/历史三路一致 | 任务 D 的改动必须保持事件序列不变；S3 改造不影响事件流 |
| 审计 fail-closed | 保留（下载仍走后端代理） |
| 并发引入的客户端限流 | **未知项**：客户 MES 是否容忍 4 路并发未经证实 → 先本机压测，必要时降 1 |
| SeaweedFS 单点 | 单节点无冗余：`seaweedfs-data` 卷必须纳入备份；本次数据是 90 天保留期的导出产物，可接受 |
| 凭据泄漏 | S3 凭据走 env（`.env` gitignore / compose env），不写入受审配置文件；端口只绑回环 |
| 匿名模式误开 | 两者都不给凭据时 SeaweedFS 会进入「Allow All」→ compose 里**必须**设置凭据，`.env.example` 给默认值并注明仅限开发 |
