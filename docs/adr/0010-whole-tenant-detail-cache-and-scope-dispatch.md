# ADR-0010：全厂明细缓存与授权范围派发

- 状态：Accepted（需求方已确认缓存范围与保留策略；客户逐组等价及容量验收尚未完成）
- 日期：2026-10-12
- 所有者：项目维护者
- 关联：`SECURITY.md`、ADR-0002、ADR-0005、`docs/product/需求及方案整理.md`、
  `docs/api/工资产量-V2.md`、`docs/api/生产进度-V2.md`

## 1. 背景

FR-001～FR-013 使用不同的分组和过滤条件，但其业务数值来自工资产量和生产进度两族。
缓存按业务底料共享，范围与展示粒度在读取时派生，避免相同数据按能力、角色或部门重复保存。
缓存必须覆盖已支持的订单列表、包级与工序级下钻，并保持现有角色矩阵和查询口径。

## 2. 决策

### 2.1 两族默认明细与辅助名册

每个已授权租户使用老板视角的两份默认明细：工资产量 `GongziClQuery` 和生产进度
`ScjdQuery`。生产者不传 `groupbyFields`，不携带员工、部门、订单、款号或物料等收窄条件。
工资底料按一致的 `Flag` / `Type` 取数；不同的语义参数保持隔离。

两族的底料服务 FR-001～FR-013 全部现有业务分支。`EmployeeQuery` 的安全名册投影复用
`identity_org` 缓存，供在册人数及身份名称解析使用；名册不作为工资或产量事实来源。
缓存保存验证过的行、footer、窗口和生成时间，不保存 LLM 文本、最终卡片或 ResultTable。

### 2.2 独立验证的老板生产者

沿用 `FACTORY_AGENT_MES_USER_CREDENTIAL_99`，支持单个加密凭据或同一配置值内的 JSON
字符串数组，不增加凭据存储源。凭据实际值只由 `data_api/owner_snapshots.py` 读取和保存。
畸形配置只报告安全类别并禁用生产者，缓存不能影响部署启动。

每个生产者经真实 token 换取及 AuthorizationService 完成授权，验证角色为老板、
`DataScope.mes_filtered` 为真、身份与租户一致，且已登记租户处于 `active`。
授权和业务取数显式绑定老板 bundle，并恢复请求者的 bundle 与日志租户上下文。
刷新后重新验证角色、身份、scope 和租户状态；身份变化不能用于重试业务请求或改写工厂归属。
多工厂生产者独立失败、独立关闭专用 adapter，共享 token exchange 由应用统一管理。

普通交互的 token 续期也不能更换租户或用户。角色或绑定部门改变时，不能沿旧 DataScope
继续业务重试和公共回填；当前交互终止该取数，下一交互使用最新身份重新授权。

### 2.3 派发与角色语义

业务请求先完成能力授权、活动租户校验及业务槽位校验，再读取公共底料。
范围、时间和业务条件的过滤发生在装载 interaction 沙箱之前：

- 员工的个人功能仅保留本人数据；组长和管理仅保留真实绑定范围。
- 老板默认按全厂读取，其最小绑定部门不能误作全厂可见范围上限；显式员工、部门等请求仍只做收窄。
- FR-004 先在获准排名人群上计算位次与组内人数，再定位并输出本人；员工角色仍不得使用该能力。
- 本人当前小组由安全名册确认；多部门绑定不能替代当前归属，缺失、不唯一或范围外时明确不可用。
- 收入按获准范围内的员工编号汇总一次；同员工跨部门或名称变化不能拆成多个人或重复输出本人。
- 订单维度使用 `jhdh`，空值统一归入「未关联计划号」，制单 `dh` 另用于标识和下钻。
- 普通请求者的实时子集、单员工/单部门结果及服务端分组结果不得回填公共老板明细键。

公共缓存不会扩大 DataScope；权限变更由新一轮真实授权决定可读视图，暂停租户仍在业务入口被拒绝。
范围外身份不会进入交互沙箱、产物、业务审计或 LLM 输入。

### 2.4 进度贡献、比率与去重边界

默认明细保留制单、真实制单业务日期 `rq`、计划、物料、包、工序、员工和部门维度，包含未扫码工序行。
已审查的列表、包级与工序级分组由取数层从过滤后的明细派生。

日期使用客户已实测返回的 `rq`，支持 ISO 日期和合法 ISO 日期时间，取字段自身业务日历日期并
标准化原 `rq`；不将日历日期当作时间点按时区偏移换日，不根据 `dh` 推断，不添加独立派生列。
缺失或非法日期拒绝缓存；按制单聚合只保留完整且唯一的日期，冲突不任选值。`rq` 动态分组
支持尚未确认，沿用已审核分组字段，不把响应字段存在当成分组支持证据。

实时原生含制单维度的分组需要日期但缺 `rq` 时，在相同授权、时间与业务条件下有界回退一次
默认明细；额外源调用如实计量。默认明细仍缺失或非法时按 `upstream_invalid` 拒绝，不能缓存
或从编号补造。原生分组正常返回 `rq` 时保留独立原生对照，不假定 `rq` 支持请求分组。

`bs`、`fhsl`、`sssl`、`zpsl`、`wgs`、`wts` 累加客户响应已给出的 sum/count 贡献。
该规则依据 V2 聚合响应契约及已记录的明细合计与 footer 可加性证据；不通过行数重建计数，
不猜测按物料或工序去重，也不把这些贡献解释为独立衣物物理件数。
同包的多工序或多员工贡献不能随意丢弃；产量跨工序相加仍须标注「件·工序」口径。
参与人数使用明确的非空员工编号 `COUNT DISTINCT`，不以明细行数代替。

`wcl = Σsssl / Σfhsl × 100`，分母为零返回零，Decimal 按 ROUND_HALF_UP 保留两位小数，
不得求和或平均行比率。未扫码的空部门组在老板视图保留，在部门视图过滤掉。
编码与名称同属一个维度；同编码冲突名称缺少客户选择规则时拒绝派生。
缺字段、不可解析贡献或未知分组规则都回退实时，不以零或空串编造数量。

`bgs` / `bts` 为不可加的纯制单参考统计，现有业务配方不消费，客户未给出其完整明细派生规则，
本实现不推断。默认明细到各服务端分组的客户逐组对账尚未完成，总合计相等不能替代该验收。

### 2.5 时间窗口、TTL 与保留

查询回溯边界保持 365 天。每日按工厂时区预取 `[今天−365, 昨天]`，凌晨 02:00 加租户抖动，
启动时可预热。已结算窗口优先从这个历史底料截取，未命中再读取问题自身完整窗口。
包含今天的窗口使用老板视角取同一个完整问题窗口，不拼接不同快照；首次冷态可能实时回源。

保留策略沿用需求方批准的分档：历史及已结算回填 24 小时，包含今天的未结算窗口 90 秒，
基础名册 24 小时。365 天是业务数据覆盖范围，**不是 Redis 条目的保留期**。

跨日优先当天底料，其次仅在完整覆盖问题窗口时读取昨天仍有效的底料，不跨窗拼接。
一轮预取固定起始工厂日期，租约、阶段及两族窗口一致，不能在午夜漂移到其它日的锁范围。
业务数据可按既有 Confidential 分类原样保存，不新增敏感字段分类或脱敏例外；凭据、密码、
accessToken、签名和提示词不进缓存。保留期或分类的后续调整仍受 SECURITY.md 的审批约束。

跨副本预取按租户及本地日期领取 Redis lease，只有两族真实写入成功才记录当日完成标记。
Redis 写失败返回失败状态并告警，不报告落盘成功。契约、指标、数据及派生规则版本变更隔离旧键。

年度老板快照采用独立有界行数预算，默认 1,000,000 行；普通问题保留既有 250,000 行预算，
页数沿用既有配置。响应超预算或行数与 total 不一致时明确不完整，不能静默裁剪后缓存为全量。
真实一年容量仍需验收，预算并不构成内存或性能承诺。

每轮预取默认限时 600 秒，租约 TTL 由该上限加安全余量计算。取数返回和缓存编码完成后、
实际写入前都检查同一截止时间；超时取消该轮、告警并重试，不写当日完成标记，拦截常见过期
回写。期限可配置。客户端有界执行不等同于 Redis 原子 fencing；任意进程挂起或已发送请求的
极端延迟需要服务端 token 条件写才能严格隔离，不以固定租约 TTL 冒充永久互斥。

### 2.6 键与版本

命名空间为 `fa:{contract}:{metric}:{data}:{tenant_sha256}:{scope_sig}:{domain}:{params_digest}`。
`tenant_sha256` 使用租户标识的 SHA-256，不在键或诊断日志直接展示 AppKey。
业务缓存域为 `v2_result`，`scope_sig=owner-99`；当前外层数据版本 `mes-detail-v4`，值版本 `v=4`，
底料粒度标识 `default-detail-v4`，日期标准化后的原 `rq` 随行集保存，`derived=[]`。内层值版本和
粒度隔离不符合当前日期契约的旧底料。预取租约、完成标记和底料处于同一数据版本命名空间，
完成标记只证明该版本两族底料已写入；启动预取不能被其它版本的标记跳过。operation、窗口及语义参数进入
参数摘要，分组、排序、角色和
用户业务收窄条件属于读取视图，不产生一份新的业务底料。

### 2.7 默认开关与最终结果影子验证

默认模式 `readwrite`。无 Redis 时直接实时；显式 `off` 完全绕过结果缓存，`read` 只读，
`shadow` 在缓存可用时仍取同口径实时数据验证，不作为延迟收益样本。

影子比较在同一个 interaction DuckDB 连接内依次执行相同受审 recipe，比较最终列、逐行结果、
名次、合计、卡片辅助输出、完整性及 warnings。原始明细行序不同不等于最终结果不同；最终排序必须
具有确定并列规则。最终不一致时返回实时结果、驱逐实际命中的键并告警，不返回经过判定的坏缓存。
缓存与实时比较使用相同的 `rq` 日期验证与标准化规则，不从制单号或其它字段补造日期。

## 3. 可观测性与降级

保留命中/未命中、来源、行数、完整性、回写失败、日期解析失败及影子不一致等安全状态。
`cache_source` 只输出来源集合和生成时间，不输出内部键、身份编号或客户行。
实际 MES 调用及耗时沿既有记录；普通热态与 shadow 分开看。辅助名册冷态和凭据交换/续期单独解释。
Redis 不可达、缓存损坏、未配置授权老板、lease 未取得、底料不完整或派生失败均可回源，
不阻塞业务答案、不把未知数量变为零、不回滚业务提交。

## 4. 验收与待验证项

本地测试覆盖两族、FR-001～FR-013、下钻、权限过滤、排名、时间窗、写失败、影子结果及多租户
生产者的合成用例。客户真实角色范围、默认明细到服务端各分组的逐组对照、倒补稳定性及一年明细
容量/内存/耗时仍需在获准环境测量；未完成这些测量，不声明已上线或承诺固定性能收益。

Redis 保留期、角色范围、客户接口聚合语义、底料字段或模型/部署边界改变时重新评审。
