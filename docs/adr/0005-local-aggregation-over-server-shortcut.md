# ADR-0005：MES 数据获取以本地加工为主，聚合短路暂不实现

- 状态：Accepted（临时决定，客户答复后可推翻）
- 日期：2026-08-24
- 所有者：项目维护者
- 关联：CQ-09、CQ-15、Story 3

## 1. 背景

CQ-09 与 CQ-15 向客户询问两件事：

- 客户 MES 是否提供服务端聚合接口（如按员工/部门/时间预聚合的产量与工资端点）；
- 平台是否可以自主组合多个基础 API 完成跨 API JOIN、GROUP BY 和 RANK。

在客户答复前，Story 3 需要确定执行内核的数据获取形态，否则 Story 5~7 的能力配方无法
落地。

## 2. 决策

在客户答复前，采用以下临时决定：

1. **本地加工为主**：所有明细数据通过 Canonical 资源型 API 拉取，跨 API JOIN、GROUP BY
   和 RANK 一律在 interaction 级内存 DuckDB 沙箱中完成。这是唯一被支持的执行路径。
2. **聚合短路暂不实现**：Catalog 不登记任何聚合型 operation；Adapter 不提供聚合端点
   形态。Story 3 清单中的"支持聚合接口短路形态"一项关闭为"按本 ADR 决定不实现"，不再
   作为未完成项阻塞 Story。
3. **Adapter 边界保持不变**：若客户后续确认存在服务端聚合，差异仍然只允许被 Adapter
   消化——同一 operation ID 可以由聚合端点应答，但必须返回等价的领域对象。届时新增一个
   Story 调整 Adapter 与 Catalog，不需要改动执行内核与配方层。
4. **预算口径不变**：本地拉全意味着分页预算必须覆盖明细行数；Mock 分页上限 200 与客户
   真实上限的差异继续作为 Story 9 双跑时的核对项。

## 3. 后果

- 正面：Story 5~7 可以立即基于单一执行路径注册配方；内核复杂度最低；沙箱逃逸面最小。
- 风险：若客户 MES 明细数据量远超预期，本地拉全的分页/行数预算可能成为性能瓶颈；
  该风险由 Story 8 性能测量验证，必要时再评估聚合短路。
- 推翻条件：客户对 CQ-09/CQ-15 给出肯定答复，或 Story 8 测量证明本地加工不可行。

## 4. 关联影响

- Story 3：清单中"支持聚合接口短路形态"标记为本决策关闭，State 可转 Resolved。
- Story 9：双跑时必须重新核对分页上限与预算配置（沿用 Story 3 已有风险记录）。
